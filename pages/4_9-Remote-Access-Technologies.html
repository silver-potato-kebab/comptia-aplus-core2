Use Remote Access Technologies

Objective 4.9 Domain weight: 21% Methods/Tools · Third-Party Tools · Security Considerations

OVERVIEWIntroduction to Remote Access

Remote access lets a technician connect to and work on a system without being physically present at it — an essential capability for supporting distributed users, managing servers in a data center, or troubleshooting a device across the building or across the world. Objective 4.9 covers the specific tools and protocols that make this possible, and just as importantly, the security posture each one carries, since opening any form of remote access to a system also opens a potential avenue for attack if it isn't configured and secured properly.

This objective covers two connected pieces. Methods/tools names the specific protocols and software technicians use for remote access — some built into the OS, some open standards, some commercial or purpose-built platforms. Security considerations is the recurring theme across every method: each one has its own authentication model, encryption story, and attack surface, and choosing the right tool for a scenario often comes down to which security trade-offs are acceptable for that situation.

Core Concept — Convenience and Attack Surface Are Linked

Every remote access method on this list exists to make a technician's job easier by removing the need to be physically present — but every one of them also creates a way into a system from the network, which is exactly what an attacker would want too. The exam consistently frames remote access as a security topic as much as a convenience topic: the right question isn't just "does this tool work," but "is this tool configured and secured appropriately for what it's being used for."

SECTION 1Methods/Tools

RDP (Remote Desktop Protocol)

RDPRemote Desktop Protocol · Microsoft
What it is A Microsoft protocol providing a full graphical remote desktop session to a Windows machine, letting the technician see and interact with the remote desktop exactly as if sitting in front of it
Typical use Remotely administering Windows workstations and servers, often within a business/domain environment

VPN (Virtual Private Network)

VPNVirtual Private Network
What it is An encrypted tunnel connecting a remote device to a private network as though it were physically on that network — a VPN itself isn't remote control of a specific machine, but rather the secure network pathway that other remote access tools (like RDP) often ride on top of
Typical use Giving remote employees or technicians secure access to internal network resources that aren't directly exposed to the public internet

VNC (Virtual Network Computer)

VNCVirtual Network Computer
What it is A cross-platform remote desktop technology providing graphical remote control, similar in purpose to RDP but not limited to Windows — VNC implementations exist for Windows, Linux, and macOS
Typical use Remote graphical access to non-Windows systems, or in mixed-OS environments where a single cross-platform remote desktop solution is preferred

SSH (Secure Shell)

SSHSecure Shell
What it is An encrypted protocol for secure command-line (text-based) remote access, most commonly used with Linux/Unix systems and networking equipment, but also available on Windows
Typical use Administering servers, network devices, and Linux systems via a secure command-line session, and securely transferring files (via related tools like SCP/SFTP)

RMM (Remote Monitoring and Management)

RMMRemote Monitoring and Management
What it is A category of platform (rather than a single protocol) that provides both remote monitoring of a device's health/status and remote management/control capability, typically used at scale across many endpoints simultaneously
Typical use Managed service providers (MSPs) and IT departments overseeing many client or company devices from a single centralized dashboard — combining monitoring, alerting, and remote access in one platform

SPICE (Simple Protocol for Independent Computing Environments)

SPICESimple Protocol for Independent Computing Environments
What it is A remote display protocol commonly associated with virtual machines, particularly in Linux/KVM virtualization environments, providing graphical remote access to a VM's console
Typical use Accessing the graphical console of a virtual machine, especially in environments built on open-source virtualization platforms

WinRM (Windows Remote Management)

WinRMWindows Remote Management
What it is Microsoft's implementation of a standard remote management protocol, allowing command-line and scripted remote administration of Windows systems — the underlying transport that tools like PowerShell remoting rely on
Typical use Scripted, automated, or command-line remote administration of Windows machines — particularly useful for running PowerShell commands or scripts (Objective 4.8) against remote systems without a full graphical session

Graphical vs. Command-Line — A Useful Grouping

A quick way to organize this list: RDP, VNC, and SPICE all provide a full graphical remote desktop/console experience. SSH and WinRM are primarily command-line/scripted access. VPN is the secure network tunnel other tools often travel through rather than an access method to a specific machine on its own. RMM is a broader management platform category that often bundles several of these underlying methods together.

Third-Party Tools

Beyond the built-in and standard protocols above, a wide range of commercial and third-party tools provide remote access and collaboration functionality, organized into four categories on the exam.

Screen-Sharing Software

  • Function — third-party platforms providing remote screen viewing/control, often easier to set up across networks than raw RDP/VNC (frequently working through NAT/firewalls without manual configuration)
  • Common use — ad hoc remote support sessions, especially for end users outside the corporate network

Videoconferencing Software

  • Function — audio/video meeting platforms, often including their own screen-sharing capability, used for verbal/visual communication alongside or instead of direct remote control
  • Common use — walking a user through a fix collaboratively, or remote meetings where direct system control isn't needed

File Transfer Software

  • Function — tools dedicated specifically to securely moving files between systems remotely, separate from a full remote-control session
  • Common use — transferring installers, logs, or diagnostic data to/from a remote system without needing a full remote desktop session

Desktop Management Software

  • Function — broader endpoint management platforms handling configuration, patching, and administration across many devices, overlapping conceptually with RMM but often more focused on desktop/endpoint configuration specifically
  • Common use — centrally managing settings, software deployment, and policy across an organization's desktop fleet

SECTION 2Security Considerations of Each Access Method

Every remote access method opens a pathway into a system, and each carries its own specific security profile — encryption strength, authentication requirements, and how attractive it is as an attack target. A technician choosing or configuring a remote access method needs to weigh these factors deliberately rather than defaulting to whichever tool is most familiar.

Universal Security Principles

  • Strong authentication — strong, unique passwords and multifactor authentication (Objective 2.1) wherever the remote access method supports it
  • Least exposure — restrict which remote access ports/services are exposed to the internet directly; prefer routing through a VPN where possible rather than exposing RDP/SSH/VNC directly
  • Encryption — ensure the connection itself is encrypted; unencrypted remote access protocols expose credentials and session data to interception
  • Least privilege — remote accounts and sessions should have only the access level actually needed for the task

Method-Specific Watch-Outs

  • RDP exposed directly to the internet — a frequent, well-known attack target for brute-force and credential-stuffing attacks; should sit behind a VPN or use additional protections (e.g., MFA, Network Level Authentication)
  • VNC — some implementations historically have weaker default authentication than RDP; verify strong authentication is configured rather than assuming it by default
  • SSH — key-based authentication is generally stronger than password authentication alone; default/weak SSH credentials are a common attack vector on internet-facing systems
  • Third-party screen-sharing tools — convenience-focused tools can sometimes trade away enterprise-grade security controls; evaluate vendor security practices before adopting for sensitive environments

Exam Angle — VPN as the Security Wrapper

A recurring scenario pattern: a technician needs to enable remote access to an internal system (via RDP, SSH, VNC, etc.) without exposing that protocol directly to the public internet. The expected answer is almost always to route that access through a VPN first, rather than opening the specific protocol's port directly on the firewall/router — minimizing the attack surface by keeping the actual remote access protocol reachable only from inside the already-authenticated VPN tunnel.

Remote Access Is a Two-Way Door

Every remote access method makes it easier for a legitimate technician to reach a system — and, if not properly secured, easier for an attacker to reach it too. This is why security considerations aren't a separate afterthought bolted onto remote access; they're the central design question for every method on this list. A scenario question that describes a remote access method being misused or exploited is almost always testing whether you recognize the specific missing safeguard (encryption, MFA, VPN wrapping, least privilege) rather than testing knowledge of the protocol itself.

Final Exam Reminders

RDP, VNC, and SPICE provide graphical access; SSH and WinRM provide command-line/scripted access — sorting each method into one of these two buckets is a fast way to reason through an unfamiliar scenario question.

A VPN is not itself "remote control" of a specific machine — it's the secure network tunnel that other remote access protocols travel through, and the exam's default expectation for securing sensitive remote access is to route it through a VPN rather than exposing the protocol's port directly.

RDP exposed directly to the internet is a well-known, frequently exploited attack target — expect this specific fact to appear in scenario questions about securing remote Windows administration.

RMM is a platform category combining monitoring and management, not a single protocol — distinguish it from the individual access methods (RDP, SSH, etc.) it might use underneath.

The four third-party tool categories — screen-sharing, videoconferencing, file transfer, desktop management — serve different specific purposes even though they can overlap in practice; know which one best matches a described need (e.g., "just needs to send a large log file" points to file transfer software, not screen-sharing).

Security considerations apply to every method, not just the "risky-sounding" ones — even RDP and SSH, both broadly trusted and widely used, require deliberate configuration (strong auth, limited exposure, encryption) to actually be safe in practice.
