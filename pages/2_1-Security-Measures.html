OVERVIEWIntroduction and the Security Layering Model

Security is not a single tool or a single decision — it is a layered strategy in which multiple overlapping controls work together so that the failure of any one control does not result in total compromise. This principle is called defense in depth: each layer makes an attacker's job harder and buys time for detection and response.

Objective 2.1 covers three distinct security domains: physical security (controls that prevent unauthorized physical access to facilities and hardware), physical access security (authentication mechanisms and devices used to control who enters physical spaces), and logical security (software-based controls that manage access to data, systems, and networks). A competent technician must understand all three domains because a technically perfect logical security architecture can be defeated by a single unlocked server room door.

How This Objective Is Tested

The "Summarize" verb means the exam tests whether you know what each control is, what threat it mitigates, and how it fits into the overall security picture. You will not be asked to configure these systems, but you will be given scenarios describing a security concern and asked which control addresses it — or asked to identify what a described control is called. Know each term's purpose and real-world appearance.

SECTION 1Physical Security

Physical security controls are designed to prevent unauthorized individuals from physically accessing facilities, hardware, and infrastructure. No amount of software-based security protects data if an attacker can walk up to a server, remove a drive, and walk out. Physical security is the outermost layer of defense in depth, and it is often the layer most taken for granted in smaller organizations.

Physical Security Controls Physical Security
Bollards
Short, heavy posts — typically concrete or steel — installed at the perimeter of a facility to prevent vehicles from ramming into a building or a secure area. They are a vehicle barrier, not a people barrier. Seen outside data centers, government buildings, and embassies. Retractable bollards allow authorized vehicles through. The threat they address: vehicle-ramming attacks and accidental vehicle incursion.
Access Control Vestibule
A small, enclosed entryway with two sets of interlocking doors — the second door cannot open until the first is closed and the individual has been authenticated. Also called a mantrap. Prevents tailgating (an unauthorized person following an authorized person through a door) because only one person can occupy the space at a time and the second door requires separate authentication. Standard in high-security areas like data centers, server rooms, and secure government facilities.
Badge Reader
An electronic device that reads a credential from an access card (magnetic stripe, RFID, proximity card, or smart card) to grant or deny entry. Badge readers maintain an audit log of every access event — who entered, when, and from which door — providing accountability that a traditional key lock cannot. Badge access can be revoked instantly when an employee leaves, whereas physical keys must be collected or locks must be changed. Works in conjunction with an access control system that manages permissions centrally.
Video Surveillance
Camera systems (CCTV and IP cameras) that record activity in and around a facility. Serve two distinct functions: deterrence (visible cameras discourage misconduct) and forensic evidence (recorded footage supports incident investigation after the fact). Modern IP-based systems allow remote monitoring and integrate with motion detection to alert security personnel in real time. Cameras should be positioned to cover all entry/exit points, server rooms, and sensitive areas. Storage retention policies govern how long footage is kept.
Alarm Systems
Electronic systems that detect unauthorized access or environmental conditions (fire, flood, temperature extremes) and trigger an alert — a local audible alarm, a silent notification to security personnel, or an automated call to emergency services. Intrusion detection alarms use door/window contacts, glass-break sensors, and motion detectors. Environmental alarms monitor temperature, humidity, water, and smoke — critical in data center environments where equipment damage can result from environmental failure.
Motion Sensors
Devices that detect movement within a defined area. Passive Infrared (PIR) sensors detect changes in heat signatures caused by a moving human body — the most common type for indoor security. Microwave and ultrasonic sensors detect movement through walls and in larger spaces. Motion sensors trigger alarms, activate lighting, start recording, or send notifications. In a server room, unexpected motion after hours is a high-priority security event.
Door Locks
The most basic physical access control. Options range from traditional keyed locks (vulnerable to lock-picking, key duplication, and lost keys) to electronic locks (cipher/keypad locks, electromagnetic locks, electric strike locks). Cipher locks use a numeric keypad code — convenient but vulnerable to code sharing and shoulder surfing. Electronic locks integrated with access control systems provide individual credential-based entry and detailed audit logs. Server rooms and telecommunications closets should always have dedicated locks separate from the general office.
Equipment Locks
Physical security devices that secure individual pieces of hardware to desks, racks, or other fixed structures. Kensington/cable locks attach a steel cable from a laptop to a fixed anchor point — standard in open office environments where laptops are left unattended. Server rack locks secure equipment within racks and restrict access to rack cabinets. Equipment locks address theft of portable hardware — particularly relevant for laptops that may contain sensitive data and are easily carried out of a building.
Security Guards
Human security personnel who provide active, adaptive, judgment-based physical security that no automated system can fully replicate. Guards can respond to alarms, verify identity through conversation and visual inspection, challenge suspicious individuals, escort visitors, and perform patrols. They are expensive compared to electronic systems but provide capabilities that cameras and locks cannot — recognizing social engineering attempts, responding to emergencies, and exercising judgment in ambiguous situations. In high-security environments, guards are combined with electronic controls.
Fences
Perimeter barriers that define the physical boundary of a secure area and delay or deter unauthorized entry. Fences serve both a physical barrier role and a psychological deterrent role — a clearly marked, fenced perimeter communicates that entry without authorization is not permitted. Chain-link fences with barbed wire (or razor wire for higher security) are standard for data center perimeters and industrial facilities. The height and construction of a fence determines how much delay it provides to an intruder.

Exam Focus — Tailgating and the Vestibule

Tailgating (also called piggybacking) is when an unauthorized person follows an authorized person through a secure door without authenticating independently. The access control vestibule (mantrap) is the specific physical control designed to prevent it. When the exam describes someone following an employee into a server room, the solution is an access control vestibule. No other control stops tailgating as effectively because it physically prevents two people from passing through simultaneously.

SECTION 2Physical Access Security

Physical access security controls are the authentication mechanisms and credential devices used to verify identity before granting physical access to a space or facility. While Section 1 covered the barriers themselves (locks, fences, vestibules), this section covers how individuals prove they are authorized to pass through those barriers. These mechanisms range from simple physical keys to advanced biometric systems.

Physical Access Credentials and Mechanisms Physical Access
Key Fobs
Small, portable hardware tokens that emit a wireless signal (typically RFID or NFC) when brought near a reader to authenticate and unlock a door or device. The user does not need to physically insert anything — they simply present the fob to the reader. Key fobs can also generate time-based one-time passwords (TOTPs) for logical system access. Advantages: easy to use, no contact required. Vulnerabilities: lost fobs grant unauthorized access until revoked, and some RFID fobs are susceptible to cloning attacks using readily available hardware.
Smart Cards
Credit-card-sized cards containing an embedded microprocessor chip that stores cryptographic keys and performs on-card computation. Unlike a simple magnetic stripe card (which passively stores data), a smart card actively participates in the authentication protocol — it can generate and sign cryptographic challenges without ever exposing the private key. Used for building access (when the reader supports smart card authentication), Windows login (PIV — Personal Identity Verification cards used in government), and CAC (Common Access Card) in the U.S. military. Significantly more secure than swipe cards because the private key never leaves the card.
Mobile Digital Key
Uses a smartphone's NFC, Bluetooth, or app-based credential as a physical access token, replacing the key fob or access card. The mobile device authenticates to a compatible lock or reader, and the door unlocks. Advantages: most people always have their phone, lost credentials can be revoked remotely via the app, and access logs are cloud-synced. Increasingly used in modern office buildings, hotel rooms, and smart home systems. Security depends on the phone itself being secured (PIN, biometric unlock) — a phone without a screen lock becomes an unrestricted master key.
Keys
Traditional physical metal keys for mechanical locks. Simple, reliable, and inexpensive — but provide no audit trail, are easily duplicated, and when lost require lock replacement to maintain security. For IT environments, physical keys remain relevant for server rack locks, cable lock anchors, equipment cabinets, and older door locks. Key management (tracking who has which keys and ensuring collection upon employment termination) is a significant operational burden in organizations that rely on physical keys at scale.
Biometrics
Authentication mechanisms that verify identity using unique physiological or behavioral characteristics of the individual. Biometrics represent the "something you are" authentication factor. Unlike passwords (something you know) or tokens (something you have), a physiological characteristic cannot be forgotten, shared, or easily transferred — but it also cannot be changed if compromised. Biometric systems measure a characteristic, create a digital template, and compare new scans against the stored template using statistical matching.
Retina Scanner
Scans the unique pattern of blood vessels in the retina at the back of the eye using low-intensity infrared light. Extremely high accuracy — the retinal pattern is one of the most unique biological features and changes very little over a lifetime. Highest security biometric. Disadvantages: requires close proximity to the scanner, perceived as intrusive, expensive, and uncomfortable for some users. Used in very high-security environments (intelligence facilities, research labs).
Fingerprint Scanner
Scans the unique pattern of ridges and valleys on the fingertip. The most widely deployed biometric technology — found in consumer laptops (Windows Hello), smartphones, and enterprise time/attendance systems. Optical (camera-based) and capacitive (measures electrical charge differences) scanners are the two most common types. Vulnerabilities include spoofing with high-quality lifted prints — mitigated by "liveness detection" (checking for temperature, pulse, or pressure variation).
Palm Print Scanner
Scans the vein structure in the palm (palm vein reader) or the ridge pattern of the entire palm. Palm vein readers use near-infrared light that penetrates the skin and maps the hemoglobin in veins — these patterns are unique, invisible on the skin surface, and essentially impossible to spoof with a copy. More hygienic than fingerprint scanners (contactless in many designs). Used in healthcare (patient identification) and high-security physical access.
Facial Recognition (FRT)
Facial Recognition Technology maps facial geometry — distances between eyes, nose, mouth, and other landmarks — and compares the map against enrolled templates. Modern implementations use 3D depth sensors (like Apple Face ID) that defeat 2D photo spoofing by requiring a three-dimensional scan. Advantages: contactless, fast, and non-intrusive. Used in Windows Hello, smartphone unlock, and airport security. Privacy concerns are significant — mass surveillance implications when deployed in public spaces.
Voice Recognition
Analyzes the unique acoustic and vocal characteristics of a person's voice — pitch, cadence, tone, and frequency patterns — and compares them to an enrolled voiceprint. Convenient for call center authentication and hands-free scenarios. Vulnerabilities: voice can change with illness, recordings can be used to replay attacks, and advanced AI voice synthesis can generate convincing spoofed voice samples. Generally considered lower-assurance than other biometrics for high-security applications.
Lighting
Adequate illumination of entry points, parking areas, pathways, and perimeter zones serves two security purposes: deterrence (criminals prefer darkness) and effectiveness of surveillance cameras (cameras require sufficient light to produce usable footage). Motion-activated lighting is especially effective — sudden illumination startles intruders and draws attention to their presence. Poor lighting is one of the most overlooked physical security gaps; a technically sophisticated access control system is undermined if the camera covering the entry has inadequate illumination to identify faces.
Magnetometers
Devices that detect the presence of ferrous (iron-containing) metal objects — primarily weapons — by measuring magnetic field distortions. The standard walk-through metal detector at airports and secure buildings is a magnetometer. Used at building entrances to detect weapons before they enter a secure area. Modern variants include hand-held wands for targeted scanning and advanced millimeter-wave scanners that can detect non-metallic threats. In the context of IT facility security, magnetometers at data center entrances also prevent unauthorized removal of magnetic media and certain storage devices.

Exam Focus — Biometric False Acceptance vs. False Rejection

Two key biometric failure modes: False Acceptance Rate (FAR) — the biometric incorrectly accepts an unauthorized person (a security failure). False Rejection Rate (FRR) — the biometric incorrectly rejects an authorized person (a usability failure). The Crossover Error Rate (CER) is where FAR and FRR are equal — it is the standard metric for comparing biometric system accuracy. A lower CER = more accurate system. Retina scanners have the lowest CER (highest accuracy); voice recognition has a higher CER (lower accuracy).

SECTION 3Logical Security — Foundational Principles

Logical security controls govern access to data, systems, applications, and networks through software-based mechanisms. While physical security prevents unauthorized physical presence, logical security prevents unauthorized digital access — even by people who are physically inside the building.

Principle of Least Privilege

The principle of least privilege (PoLP) states that every user, process, application, and system component should be granted only the minimum level of access rights necessary to perform its legitimate function — nothing more. A user who needs to read reports does not need to write or delete them. A service account that queries a database does not need DBA privileges. A standard workstation user does not need administrator rights.

Why It Matters Least privilege limits the blast radius of a compromised account or application. If an attacker compromises a standard user account with minimal rights, they can cause less damage than if they compromise an administrator account. Malware running under a restricted user context has limited ability to spread or modify the system compared to malware running as SYSTEM.
Implementation Use standard user accounts for day-to-day work — even IT administrators should have a separate admin account used only when elevation is needed. Remove administrator rights from standard users. Use Role-Based Access Control (RBAC) to define roles with specific, minimal permissions. Audit permissions regularly and remove access when it is no longer needed (access creep).
Access Creep The gradual accumulation of permissions over time as a user changes roles, takes on projects, or requests access that is never revoked. Regular access reviews (quarterly or annually) identify and remove stale permissions. Access creep is a violation of least privilege that grows silently over time.

Zero Trust Model

The Zero Trust model is a security architecture built on the principle "never trust, always verify." It rejects the traditional network security model in which everything inside the corporate network perimeter is trusted. In Zero Trust, no user, device, or network segment is inherently trusted — every access request must be authenticated, authorized, and continuously validated regardless of where it originates.

Why Zero Trust Replaced Perimeter Security

The traditional "castle and moat" model — where internal users are trusted and external users are not — fails in the modern threat environment. Employees work remotely (outside the perimeter), cloud services live outside the traditional network, and attackers regularly compromise internal accounts. Once inside the perimeter, a threat actor in the old model had broad access. Zero Trust eliminates the concept of "inside = trusted" entirely. Every connection is treated as if it comes from an untrusted, hostile network.

Verify Explicitly Always authenticate and authorize every request based on all available data points — identity, location, device health, service/workload, data classification, and anomalies. Strong multi-factor authentication is a cornerstone of Zero Trust implementation.
Use Least Privilege Access Limit user access with just-in-time and just-enough-access policies. Minimize exposure by granting temporary, scoped access to specific resources when needed rather than broad, persistent access.
Assume Breach Design and operate as if a breach has already occurred or will occur. Minimize the blast radius by segmenting access. Use end-to-end encryption. Monitor everything to detect anomalies quickly and reduce dwell time (the time an attacker has before detection).

Access Control Lists (ACLs)

An Access Control List (ACL) is an ordered list of rules that define what actions (read, write, execute, delete, etc.) a subject (user, group, process, IP address) is allowed or denied on an object (file, directory, network resource, firewall interface). ACLs are the fundamental mechanism by which permissions are enforced in both file systems and networks.

File System ACLs On NTFS volumes, every file and folder has a Discretionary ACL (DACL) that lists which users and groups have which permissions (Full Control, Modify, Read & Execute, Read, Write). NTFS also maintains a System ACL (SACL) that defines which access events to audit (log). ACL entries are called Access Control Entries (ACEs).
Network ACLs On routers, switches, and firewalls, ACLs are rule sets that permit or deny network traffic based on source IP, destination IP, protocol, and port. A firewall's rule set is essentially an ACL applied to network packets. Processed top-to-bottom; the first matching rule is applied. Most implementations have an implicit "deny all" at the end.
Explicit Allow vs. Deny An explicit Deny in an ACL overrides an Allow. If a user is a member of two groups — one with Read permission and one with an explicit Deny — the Deny wins. This is important for troubleshooting unexpected "access denied" errors: look for explicit deny ACEs in the object's permission list.

SECTION 4Multifactor Authentication (MFA)

Multifactor Authentication (MFA) requires a user to present two or more verification factors from different categories to prove identity. The three authentication factor categories are: something you know (password, PIN, security question), something you have (hardware token, smart card, phone), and something you are (biometric). Two factors from the same category (e.g., two passwords) is not MFA — the factors must come from at least two different categories.

Exam Focus — What Counts as MFA

A password alone = single factor (something you know). A password + SMS code = MFA (something you know + something you have). A fingerprint alone = single factor (something you are). A fingerprint + PIN = MFA (something you are + something you know). Two passwords = NOT MFA — same category. This distinction is frequently tested with scenarios asking "is this MFA or not?"

Hardware Token

A dedicated physical device (RSA SecurID, YubiKey) that generates or stores authentication codes. Completely offline and independent of any network. Cannot be phished remotely.

Highest Assurance

Authenticator App (TOTP)

A smartphone app (Google Authenticator, Microsoft Authenticator, Authy) that generates time-based codes. Codes are generated locally; no internet or carrier needed. Phishing-resistant if the user verifies the site before entering the code.

High Assurance

TOTP (Time-Based OTP)

A one-time password algorithm (RFC 6238) that generates a 6–8 digit code by combining a shared secret key with the current time. Codes change every 30 seconds. Used by both hardware tokens and authenticator apps.

High Assurance

Email-Based Code

A one-time code sent to the user's email address. Security depends on the email account's own security — if the email account is compromised, this MFA factor is also compromised.

Medium Assurance

Voice Call

An automated phone call reads a one-time code to the user. Shares SMS vulnerabilities (SS7 protocol weakness, phone number porting attacks) but useful for users who cannot receive text messages.

Medium Assurance

SMS (Text Message)

A one-time code sent via text message. Convenient but vulnerable to SIM-swapping attacks (attacker convinces carrier to port the number), SS7 interception, and malware on the device that intercepts texts. NIST recommends against SMS for high-security use cases.

Lower Assurance

OTP vs. TOTP

OTP (One-Time Password) A generic term for any password that is valid for a single use. Once used (or after it expires), it cannot be used again. This prevents replay attacks — even if an attacker intercepts the code, it is already invalid by the time they try to use it. OTP is the category; TOTP and HOTP are specific implementations.
TOTP (Time-Based OTP) Generates codes using the current time as an input to a shared algorithm. Both the authenticator and the server know the same secret key and the current time, so they independently calculate the same code. Codes are valid for a short window (typically 30 seconds) to allow for minor clock drift between devices.
HOTP (HMAC-Based OTP) Generates codes using a counter rather than time. Each authentication increments the counter. The code is valid until used, not time-limited. Less commonly tested but understanding the distinction from TOTP is useful.

SECTION 5Logical Access Technologies

SAML — Security Assertions Markup Language

Security Assertions Markup Language (SAML) is an open XML-based standard for exchanging authentication and authorization data between an Identity Provider (IdP) and a Service Provider (SP). It is the underlying protocol that makes federated identity and enterprise Single Sign-On possible across organizations and cloud services.

Identity Provider (IdP) The system that authenticates the user and vouches for their identity. Examples: Microsoft Entra ID (formerly Azure AD), Okta, ADFS (Active Directory Federation Services). The IdP holds the user's credentials and performs the actual authentication.
Service Provider (SP) The application or resource the user wants to access. Examples: Salesforce, Google Workspace, a corporate web app. The SP trusts the IdP's assertions and grants access based on what the SAML assertion says about the user's identity and attributes.
SAML Assertion An XML document the IdP sends to the SP containing: the user's identity, when they authenticated, what authentication method was used, and what attributes (roles, groups, email) they have. The SP uses this information to make an access decision without ever seeing the user's password.
Real-World Use When a corporate employee logs into their company portal (authenticating against the company's Active Directory / Entra ID), and is then automatically logged into Salesforce, Workday, Office 365, and other cloud apps — SAML is the protocol making that seamless transition possible.

Single Sign-On (SSO)

Single Sign-On (SSO) is an authentication method that allows a user to log in once and gain access to multiple applications and services without re-entering credentials for each one. The user authenticates to a central identity provider, which issues tokens or assertions used to automatically log into connected services.

User Experience A user logs into their Windows domain at the start of the day (authenticating once with their domain credentials and MFA). For the rest of the day, they access email, SharePoint, Salesforce, the HR system, and other applications automatically — no additional login prompts. Reduces password fatigue and help desk calls for password resets.
Security Trade-off SSO concentrates authentication into a single point. If that central identity is compromised (the user's domain account is stolen), the attacker gains access to all SSO-connected services simultaneously. This is why MFA is critical on the SSO-protected account — the central authentication event must be strongly secured.
SSO vs. SAML SSO is the user experience (log in once, access many). SAML is one of the protocols that implements SSO across federated systems. Other protocols that enable SSO include OAuth 2.0 and OpenID Connect (OIDC). SAML is the enterprise standard; OIDC/OAuth is dominant in consumer applications.

Just-in-Time Access and PAM

Just-in-time (JIT) access is a security model in which elevated privileges are granted only for the specific time window and task that requires them, rather than being permanently assigned to an account. An administrator who needs to perform a privileged operation requests access, it is approved and granted for a defined window (e.g., 1 hour), and then automatically revoked when the window expires.

Privileged Access Management (PAM) Logical Security
What is PAM
Privileged Access Management is the category of tools and practices that control, monitor, and audit access to privileged accounts — accounts with elevated rights such as domain administrators, local administrators, root accounts, and service accounts. PAM solutions enforce just-in-time access, require justification for privilege elevation, record sessions for audit, and automatically rotate credentials.
Why It Matters
Privileged accounts are the highest-value targets for attackers. A compromised privileged account can modify security policies, disable logging, exfiltrate data, and move laterally through the entire organization. PAM limits the time window during which privileged credentials are valid and in use, dramatically reducing the attack surface.
Session Recording
PAM solutions record privileged sessions (what commands were run, what files were accessed, what was changed) — creating an immutable audit trail. This supports incident investigation, compliance requirements, and insider threat detection.
Credential Vaulting
Privileged credentials (administrator passwords, service account passwords) are stored in an encrypted vault managed by the PAM system. Users check out credentials for a session; after the session ends, the password is automatically rotated. This means no human ever knows the standing password for privileged accounts.

Mobile Device Management (MDM)

Mobile Device Management (MDM) is a software solution that allows an organization to centrally manage, monitor, configure, and enforce security policies on mobile devices (smartphones, tablets) used to access corporate resources — whether those devices are company-owned or personal (BYOD — Bring Your Own Device).

MDM Capabilities Logical Security
Policy Enforcement
Remotely push security policies to enrolled devices: require screen lock PIN/biometric, enforce minimum OS version, require encryption, disable the camera in secure areas, restrict which apps can be installed, and enforce VPN usage for corporate traffic.
Remote Wipe
If a device is lost or stolen, the MDM administrator can issue a remote wipe command that erases all data on the device. On BYOD devices, a selective wipe removes only corporate data and applications, leaving personal data intact.
Application Management
MDM can push approved apps to enrolled devices, blacklist unauthorized apps, and distribute corporate-specific apps through a private app catalog. Ensures that corporate data is only accessed through approved, secure applications.
Device Inventory
Maintains a real-time inventory of all enrolled devices including OS version, patch level, installed applications, and compliance status. Non-compliant devices (e.g., jailbroken, outdated OS) can be automatically quarantined from corporate resources.
BYOD Considerations
BYOD enrollment means employees accept MDM on their personal devices in exchange for corporate access. Privacy implications must be clearly communicated — employees should understand what the MDM can and cannot see on their personal device. Enterprise MDM typically creates a containerized workspace that keeps corporate and personal data separated.

Data Loss Prevention (DLP)

Data Loss Prevention (DLP) refers to a set of tools and processes designed to detect and prevent sensitive data from leaving the organization in unauthorized ways — whether by accident or malicious intent. DLP monitors data in use (on endpoints), data in motion (traversing the network), and data at rest (stored on systems).

Data in Motion (Network DLP) Inspects network traffic (email, web uploads, cloud sync, FTP, messaging) for content that matches sensitive data patterns — credit card numbers, Social Security Numbers, healthcare records, source code, or keywords defined by policy. Can block, quarantine, or alert on policy violations before data leaves the network perimeter.
Data at Rest (Storage DLP) Scans data stored on file servers, databases, email archives, and cloud storage to identify sensitive data that is stored in insecure locations, has overly permissive access controls, or is unencrypted. Helps organizations find sensitive data they did not know they had.
Data in Use (Endpoint DLP) Agent software on endpoints monitors what users do with data — copying files to USB drives, printing documents, taking screenshots, or uploading files to personal cloud accounts. Can block prohibited operations or require justification before allowing them.
Content Inspection DLP uses pattern matching (regex for credit card numbers, SSNs), fingerprinting (matching against known sensitive document templates), and machine learning to identify sensitive content — not just by file type or label, but by the actual content of the data.

Identity Access Management (IAM)

Identity and Access Management (IAM) is the framework of policies, processes, and technologies that manage digital identities and control what those identities are authorized to access. IAM encompasses the entire lifecycle of an identity — from provisioning when a user joins, through modifications as their role changes, to deprovisioning when they leave.

IAM Components Logical Security
Identity Lifecycle
Joiner — new employee joins; IAM provisions accounts, assigns roles, grants access. Mover — employee changes role; IAM modifies access to match new responsibilities and removes old access. Leaver — employee departs; IAM immediately deprovisions all accounts and revokes access across all connected systems. This last step is critical — unrevoked accounts of departed employees are a major security risk.
Role-Based Access Control
Rather than assigning permissions directly to users, RBAC assigns permissions to roles (e.g., "Finance Analyst," "IT Administrator," "HR Manager"), and users are assigned to roles. This simplifies management — when a role's permissions change, all users in that role are automatically updated. It is the practical implementation of least privilege at scale.
Provisioning & Deprovisioning
Automated IAM solutions synchronize with HR systems so that when an employee's record is updated (hired, transferred, terminated), the corresponding system access is provisioned, modified, or revoked automatically — reducing the window during which stale access exists. Manual processes are slow and error-prone.
Access Certification
Periodic reviews where managers certify that their team members still require the access they have been granted. Any access that cannot be justified is revoked. Addresses access creep (the accumulation of permissions over time) and is often required for compliance frameworks (SOX, HIPAA, PCI-DSS).

Directory Services

Directory services are centralized database systems that store, organize, and provide access to information about network resources — users, computers, groups, printers, and policies — in a hierarchical structure. They are the backbone of identity and access management in enterprise environments.

Active Directory (AD) Microsoft's directory service, built on the LDAP (Lightweight Directory Access Protocol) protocol. The dominant enterprise directory service. Stores user accounts, computer accounts, groups, Group Policy Objects (GPOs), and organizational units (OUs) in a domain. Domain Controllers (DCs) run Active Directory and handle authentication (Kerberos protocol) and authorization for all domain-joined machines. When a user logs into a domain-joined Windows machine, Active Directory authenticates them and delivers applicable Group Policy.
LDAP The protocol used to query and modify directory services. LDAP defines the structure of directory entries (Distinguished Names, attributes) and the operations that can be performed (search, add, modify, delete, authenticate). Most enterprise directory services (Active Directory, OpenLDAP) support LDAP. Applications integrate with directory services via LDAP queries to verify user credentials and retrieve user attributes.
Entra ID (Azure AD) Microsoft's cloud-based identity and access management service — the cloud counterpart to on-premises Active Directory. Provides SSO to cloud applications, MFA management, conditional access policies, and device management. Used in hybrid environments where some resources are on-premises (AD) and some are in the cloud (Entra ID).
Organizational Units (OUs) Containers within Active Directory that organize objects (users, computers, groups) into a hierarchical structure reflecting the organization's geography, department, or function. Group Policy Objects are linked to OUs, so settings are applied to all objects within an OU. OUs enable delegated administration — an OU administrator can manage objects within their OU without having domain-wide admin rights.

Connecting the Dots: IAM, Directory Services, SSO, and SAML

These logical security technologies work together as a system: Active Directory (or Entra ID) is the directory service that stores all identity data. It serves as the Identity Provider for the organization. Users authenticate once to Active Directory (through Kerberos/NTLM on-premises or SAML/OIDC for cloud apps) — this is the SSO authentication event. SAML is the protocol that carries the authentication assertion to cloud services. IAM governs the entire lifecycle of who is in the directory and what they are allowed to access. MDM ensures the devices used to access these resources are compliant. MFA strengthens the initial authentication event. DLP watches what happens to data once the authenticated user has access. All of these layers together constitute a comprehensive logical security architecture.

High-Probability Exam Scenarios

Scenario 1: An employee holds the door open for a visitor entering a secure area → Tailgating. Solution: access control vestibule (mantrap).
Scenario 2: A car drives through the lobby of a building → Vehicle ramming. Solution: bollards.
Scenario 3: A user changes jobs but still has access to old department files → Access creep. Solution: IAM access review / least privilege enforcement.
Scenario 4: An attacker steals a user's password and logs in → Password-only auth insufficient. Solution: MFA.
Scenario 5: An employee uses their phone as a building access credential → Mobile digital key.
Scenario 6: A company wants employees to log into Salesforce without a separate password → SSO (implemented via SAML).
Scenario 7: An IT admin needs domain admin rights only for a specific 1-hour maintenance task → Just-in-time access via PAM.
Scenario 8: A terminated employee's accounts must be immediately revoked across all systems → IAM deprovisioning (Leaver process).
Scenario 9: Finance files are being emailed to personal Gmail accounts → Data exfiltration. Solution: Data Loss Prevention (DLP).
Scenario 10: A lost company phone with sensitive data → MDM remote wipe.
