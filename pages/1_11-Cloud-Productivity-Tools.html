OVERVIEWIntroduction

Cloud-based productivity tools have become the dominant software model for business computing. Rather than installing applications on individual machines and managing local license keys, organizations now provision accounts through central directories — and users access their email, documents, spreadsheets, video calls, and chat from any device with a browser or a lightweight installed client. For an A+ technician, this shift means the job has evolved: instead of running setup wizards, you are connecting users to cloud platforms, configuring sync settings, troubleshooting account provisioning, and ensuring licenses are correctly assigned.

This objective covers the full scope of what that entails: understanding the major cloud productivity platforms and what each component does, configuring email profiles and storage sync, deploying collaboration tools, and managing identity synchronization and licensing at the administrative level. The scenarios on the exam present real technician tasks — a user whose OneDrive isn't syncing, a new employee who needs a Microsoft 365 license, a video call tool that needs to be configured — and require you to identify the correct steps.

Platform Scope

The exam is platform-agnostic — it tests concepts that apply across Google Workspace (formerly G Suite), Microsoft 365 (formerly Office 365), and Apple iCloud. Scenarios may name a specific platform, so recognizing the equivalent tool in each suite is important. The coverage below addresses all three, with emphasis on Google Workspace and Microsoft 365 as the dominant enterprise platforms.

Section AWhat Cloud-Based Productivity Means

A cloud-based productivity suite is a collection of business applications — email, word processing, spreadsheets, presentations, video conferencing, chat, and file storage — delivered as a service over the internet. The applications may be accessed entirely through a web browser, installed as desktop/mobile clients that sync with the cloud, or both. The defining characteristic is that the data lives in the cloud provider's infrastructure, not on the local machine.

Section BEmail Systems

Cloud email is the most universally deployed cloud productivity component. Unlike on-premises mail servers that require a technician to maintain Exchange or Postfix infrastructure, cloud email is entirely managed by the provider — the technician's role is configuration: setting up the mail client to connect to the cloud service, configuring the account in mobile and desktop apps, and troubleshooting connectivity and authentication issues.

Exchange Online setup
Microsoft 365 email is powered by Exchange Online. Setting up email in Outlook: enter the user's email address (e.g., user@company.com) and Outlook queries Autodiscover — a DNS service record that returns the correct server configuration automatically. Modern authentication (OAuth 2.0) then prompts for the Microsoft 365 password and may trigger MFA. No manual server settings are required in most deployments. For manual setup: incoming server outlook.office365.com (IMAP port 993 SSL or POP3 port 995), outgoing SMTP smtp.office365.com port 587 (TLS). In enterprise environments, the IT admin configures Exchange Online settings centrally through the Microsoft 365 Admin Center → Exchange Admin Center.
Gmail / Google Workspace
Google Workspace email is Gmail with a custom domain. In the Gmail web interface, no client configuration is needed — users log in at mail.google.com with their Workspace credentials. For third-party email clients (Outlook, Thunderbird, Apple Mail), enable IMAP in Gmail settings (Settings → Forwarding and POP/IMAP → Enable IMAP), then configure the client with IMAP server imap.gmail.com port 993 (SSL) and SMTP smtp.gmail.com port 465 or 587. Google requires an App Password for clients that don't support OAuth — generated in Google Account → Security → App Passwords (requires 2-Step Verification to be enabled). In enterprise Workspace, app passwords may be managed via admin policy.
Email protocols recap
IMAP (port 143/993) — Internet Message Access Protocol; messages stay on the server, client shows a synchronized view; deleting on one device deletes everywhere. POP3 (port 110/995) — Post Office Protocol 3; downloads messages to the local device and (optionally) deletes from server; works offline but messages are not synchronized across devices. For cloud email, IMAP is the correct choice — POP3 defeats the purpose of cloud storage by pulling everything local. SMTP (port 25/465/587) — Simple Mail Transfer Protocol; outbound only; always used for sending regardless of which protocol handles receiving.
Mobile email configuration
On iOS/Android, email is configured in the native mail app or through Microsoft Outlook for Mobile / Gmail app. iOS automatically detects Microsoft 365 and iCloud configurations when the email address is entered — entering user@company.com triggers Autodiscover and the account is set up automatically. For Google Workspace accounts, the Gmail app on Android/iOS only requires email and password. In MDM (Mobile Device Management) environments, email profiles are pushed to devices automatically — the user's device receives the Exchange/Google profile silently when enrolled, with no manual configuration needed.
Spam and mail flow
Cloud email platforms include built-in spam filtering and policy enforcement. Microsoft 365 uses Exchange Online Protection (EOP) and optionally Defender for Office 365 for anti-phishing, anti-malware, and link detonation. Google Workspace includes Gmail's spam filter with configurable policies in the admin console. Technicians may be asked to: whitelist a sender (add to the safe senders list), release a quarantined message, or configure an email flow rule (transport rule in Exchange / routing rule in Google Workspace). These are done in the respective admin consoles, not individual client settings.

Section CCloud Storage — Sync and Folder Settings

Cloud storage services provide a synchronized folder on the user's device that mirrors content to and from the cloud. Files placed in the synced folder are automatically uploaded to the cloud and pushed to all other signed-in devices. For a technician, the task is installing and configuring the sync client, setting up folder selections, troubleshooting sync errors, and understanding how selective sync and shared drives work.

Setting up OneDrive sync
OneDrive is built into Windows 10 and 11. Sign in: click the OneDrive cloud icon in the system tray → Sign in → enter Microsoft 365 email → authenticate. Windows then syncs the user's OneDrive folder to C:\Users\[username]\OneDrive - [Organization]. The folder appears in File Explorer alongside local folders. Any file saved here is automatically uploaded. First-time sync on a large account can take minutes to hours depending on data volume and connection speed — the icon animates while syncing and becomes a static cloud when complete.
Selective sync / Files On-Demand
Files On-Demand (enabled by default in Windows 10/11) shows all OneDrive files in File Explorer without downloading them — they download on first open. File status icons: cloud icon = online only (not downloaded, no local copy); sync arrows = currently syncing; green checkmark = available locally (full copy on disk); solid green checkmark = always keep on device. Right-click any file or folder → Always keep on this device to force a local download. Right-click → Free up space to convert a local file back to online-only. This is critical for laptops with limited storage — only frequently used files need to occupy local disk space.
Selective folder sync
To control which OneDrive folders sync to a specific device: right-click the OneDrive icon in system tray → Settings → Account → Choose folders. Uncheck folders that should not sync locally. This does not delete files from OneDrive — it just removes them from the local device. Useful when a workstation has limited disk space but the user's OneDrive contains large archive folders they rarely access from that machine.
SharePoint and shared libraries
SharePoint Online is the team-level storage in Microsoft 365 — document libraries shared across a department or team, as distinct from a user's personal OneDrive. SharePoint libraries can be synced to the local device using the same OneDrive sync client: in SharePoint → navigate to the library → click Sync. The library appears in File Explorer under C:\Users\[username]\[Organization]. SharePoint libraries support versioning, check-in/check-out, and permissions management — features that individual OneDrive does not have. Microsoft Teams stores its files in SharePoint libraries behind the scenes.
Troubleshooting OneDrive sync
Common sync issues and fixes: Red X on files — file is in a conflict state or has a name with illegal characters (: * ? < > | " /); rename the file. Sync paused — OneDrive pauses sync when battery saver is active, metered connection detected, or storage is nearly full; address the condition. Account not connected — user's password changed; click the OneDrive icon → Sign In. Files not appearing on another device — check sync is not paused on the source device; check available cloud storage quota (OneDrive icon → Settings → Account → shows used/available). Reset OneDrive: run %localappdata%\Microsoft\OneDrive\onedrive.exe /reset — resets sync engine without deleting files.
Google Drive — Google Workspace Cloud Storage
Drive for desktop sync client, Shared Drives for team storage
Google Workspace
Drive for Desktop
Google Drive's desktop sync application is called Drive for Desktop (formerly Backup and Sync / Google Drive File Stream). Install from drive.google.com/drive/download. After sign-in, Drive for Desktop creates a virtual drive letter (G:\ or the next available letter) that shows all Drive content without downloading it — similar to OneDrive's Files On-Demand. Files download when opened. Alternatively, specific local folders can be mirrored to Google Drive so they sync bidirectionally.
Mirror vs. Stream
Drive for Desktop offers two sync modes: Stream files — all Drive content is visible as a virtual drive; files download on demand; minimal local disk usage. Mirror files — selected folders are fully downloaded and kept in sync bidirectionally; files are always available offline. Configure in Drive for Desktop preferences → My Drive syncing options. For users who frequently work offline (travelers, those with unreliable connections), Mirror mode ensures files are always available. For users with large Drives on small disks, Stream mode is appropriate.
Shared Drives
Shared Drives (formerly Team Drives) are Google Workspace's equivalent of SharePoint — storage owned by the organization rather than any individual user. When an employee leaves, their files remain in the Shared Drive. Shared Drives appear in Drive for Desktop alongside My Drive. Permissions are managed by Workspace admins: Manager, Content Manager, Contributor, Commenter, Viewer. Files in Shared Drives can be synced locally using Drive for Desktop's Stream or Mirror mode just like personal Drive content.
Storage quota management
Google Workspace storage is pooled across the organization rather than per-user (in newer plans). Admins monitor usage in the Google Admin Console → Reports → Storage. Individual users see their quota at one.google.com/storage. Gmail, Drive, and Google Photos all count against the quota. When a user's quota is full, they cannot receive new emails or upload new files — addressing quota requires the admin to either upgrade the plan or have the user delete unnecessary content. In enterprise environments, storage limits are configurable per organizational unit (OU).

Section DCollaboration Tools

Cloud productivity suites bundle a full set of collaboration applications — word processing, spreadsheets, presentations, video conferencing, and instant messaging. A technician needs to know which application in each suite serves each function, how to install and configure the desktop clients, and how to troubleshoot the most common issues users encounter.

Word Processing Tools

Word Processing — Cloud Docs
Microsoft Word / Word Online · Google Docs · Apple Pages
Docs
Microsoft Word / Word Online
Microsoft 365 includes the full desktop Word application (installed via Microsoft 365 Apps deployment) and Word Online (browser-based, lighter feature set). Files are saved to OneDrive or SharePoint in .docx format. Real-time co-authoring allows multiple users to edit simultaneously — changes appear in near-real-time with colored cursor indicators showing each user's position. AutoSave continuously saves changes to the cloud when the file is stored in OneDrive/SharePoint — the floppy disk save button is replaced by an AutoSave toggle. A user who complains that Word is not saving may have AutoSave disabled or the file stored locally rather than in OneDrive.
Google Docs
Google Docs is entirely browser-based — no installation required. Files are stored in Google Drive in native Docs format (.gdoc links, not traditional files), though they can be exported as .docx or PDF. Real-time collaboration is a core strength — multiple editors are indicated by colored cursor icons with name labels. Version history (File → Version history → See version history) shows every edit with timestamp and author — documents can be restored to any previous version. Docs auto-saves every few seconds with no manual save required. For users working offline, Docs requires enabling offline mode in Drive settings first.
File format compatibility
A common technician task is handling file format compatibility between Google Docs and Microsoft Word. Opening a .docx in Google Docs — Google Drive opens Word files natively in Docs; complex formatting may not render perfectly. Exporting from Docs to .docx — File → Download → Microsoft Word (.docx). Converting Drive files to Office format by default — Google Admin Console → Google Workspace → Drive and Docs → Features and Applications → enable "Create files in Office formats." This ensures new documents created in Docs default to .docx, simplifying collaboration with non-Google users.

Spreadsheets

Spreadsheets — Cloud Sheets
Microsoft Excel / Excel Online · Google Sheets · Apple Numbers
Sheets
Microsoft Excel Online
Excel Online is the browser-based version of Excel, available through Microsoft 365. It supports most common Excel functions, charts, and pivot tables but lacks some advanced features (Power Query, certain VBA macros). Files are stored as .xlsx in OneDrive/SharePoint. The full desktop Excel application is available to users with Microsoft 365 Apps licensing. When a user reports that Excel macros are not running in the browser version, the correct response is that VBA macros require the desktop application — Excel Online does not support VBA execution. Co-authoring works in both Online and desktop versions when files are saved to OneDrive/SharePoint.
Google Sheets
Google Sheets is browser-native and supports Google Apps Script for automation (the Google equivalent of VBA macros). Data can be imported from and exported to .xlsx, .csv, and other formats. A significant Sheets feature relevant to technicians is Google Forms → Sheets integration — responses from Google Forms are automatically populated into a linked Sheets spreadsheet, which is commonly used for IT inventory tracking, help desk intake forms, and asset management in SMB environments. Sheets supports up to 10 million cells per spreadsheet — large data sets that exceed this require BigQuery or other data solutions.

Presentation Tools

Presentation Tools
Microsoft PowerPoint / PowerPoint Online · Google Slides · Apple Keynote
Slides
PowerPoint vs. Google Slides
Microsoft PowerPoint (desktop and Online) stores files as .pptx and is the industry standard for business presentations. Google Slides is browser-based and stores natively in Drive, exportable as .pptx. A common technician scenario: a user shares a .pptx file received via email and reports that it does not display correctly. Resolution options: open in the full desktop PowerPoint application for best fidelity; or convert to Google Slides, accepting that some formatting (custom fonts, animations, embedded media) may not transfer perfectly. For presenting directly from a browser, both PowerPoint Online and Google Slides support presenter mode with speaker notes.
Sharing and presenting
Both platforms support sharing presentations with view-only or edit access. Google Slides: Share button → enter email addresses or generate a shareable link with configurable permissions (Viewer, Commenter, Editor). PowerPoint Online: Share → invite people (Microsoft 365 users) or copy link with configurable permission (Can view / Can edit). For presenting during a video call (Teams, Meet, Zoom), the presenter shares their screen or uses the video platform's built-in presentation mode, which can show slides without sharing the entire desktop.

Microsoft Teams
Microsoft Teams is the unified communication and collaboration hub in Microsoft 365 — it combines video meetings, persistent chat (channels and direct messages), file sharing (backed by SharePoint), and app integrations in one application. Install: Microsoft 365 Apps installation includes Teams by default, or download separately from teams.microsoft.com. Sign in with Microsoft 365 credentials. Google Meet
Google Meet is included in all Google Workspace tiers and is accessible directly from Gmail, Google Calendar, and meet.google.com. No separate download is required for browser-based use; a lightweight app is available for Android/iOS. Zoom
Zoom is a third-party videoconferencing platform that works alongside or instead of the suite-integrated tools. Install: download Zoom client from zoom.us/download — organizations often deploy this via software management tools (Intune, JAMF, SCCM). Zoom integrates with both Microsoft 365 and Google Workspace calendars via add-ins/extensions that add a "Zoom" button to meeting invitations. Key settings: Virtual background requires a CPU or GPU that supports it; some older machines cannot run Zoom virtual backgrounds. Screen sharing permissions can be restricted by the host — technicians may need to enable screen sharing in Zoom account settings for users who report they cannot share their screen in meetings.
Hardware requirements and troubleshooting
Videoconferencing requires a functioning camera, microphone, and speakers/headset. Common technician issues: Camera not working in meeting app — check OS privacy settings (Windows: Settings → Privacy → Camera; macOS: System Preferences → Security → Camera) — the app must be granted camera access. Echo or audio feedback — user's microphone is picking up speaker output; solution: use headphones or headset instead of built-in speakers. Poor video quality / pixelation — insufficient bandwidth; video uses 1–4 Mbps for HD; test connection speed or reduce video quality in the app settings. Meeting audio heard but no video — camera driver issue or camera covered/disabled; verify in Device Manager.

Section EIdentity Synchronization

Identity synchronization is the process of keeping user accounts consistent between an on-premises directory (Active Directory) and a cloud identity provider (Microsoft Entra ID / Azure AD, Google Workspace Directory). In hybrid organizations — those with both on-premises infrastructure and cloud services — a single user must have a consistent identity that allows them to sign in to both local Windows workstations and cloud applications with the same credentials. Identity sync is what makes this possible.

What it does
Microsoft Entra ID Connect (formerly Azure AD Connect) is a service installed on a Windows Server on the organization's network. It reads user and group objects from on-premises Active Directory and replicates them to Microsoft Entra ID (the cloud identity service backing Microsoft 365). Once synchronized, a user created in Active Directory automatically appears in Microsoft 365 within 30 minutes — their username, email address, group memberships, and password hash are mirrored to the cloud. Technicians do not typically install or configure Entra ID Connect directly (that is an admin/architect task), but they need to understand what it does to diagnose identity issues.
Password Hash Sync vs. Pass-Through Auth
Entra ID Connect supports several authentication modes. Password Hash Synchronization (PHS) — the hash of the user's on-premises AD password is synchronized to Entra ID; users authenticate directly to the cloud; works even if on-premises servers are down. Pass-Through Authentication (PTA) — authentication requests from the cloud are forwarded to on-premises AD in real time; the password hash never leaves the premises; requires on-premises infrastructure to be available for cloud login. Federation (AD FS) — a dedicated federation server issues tokens; most complex, highest cost, used by large enterprises with strict compliance requirements. For most organizations, PHS is the recommended and most resilient option.
Single Sign-On (SSO)
Seamless Single Sign-On is a companion feature to Entra ID Connect that allows users logged into a domain-joined Windows machine to access Microsoft 365 cloud applications (Outlook, Teams, SharePoint) without re-entering credentials — the Kerberos ticket from Windows login is used transparently to obtain a cloud token. From the technician's perspective, SSO "just works" once properly configured by the admin, but failures manifest as users being unexpectedly prompted for credentials in Microsoft 365 apps. Common cause: the user's machine is not domain-joined, or the Workplace Join / Hybrid Azure AD Join registration has failed — check in Settings → Accounts → Access work or school → view account details to confirm the device registration state.
Google Workspace — Directory Sync
Google Workspace uses Google Cloud Directory Sync (GCDS) to synchronize users from on-premises Active Directory or LDAP directories to the Google Workspace directory. Like Entra ID Connect, GCDS is installed on an on-premises server and runs on a schedule. It is unidirectional — AD is the source of truth, GCDS pushes to Google. Changes made in the Google Admin Console may be overwritten at the next sync cycle. Google Workspace also supports SAML-based SSO with an on-premises identity provider (AD FS, Okta, Ping) — users are redirected to the corporate identity provider for authentication rather than entering their Google password.
Cloud-only identity
Organizations without on-premises Active Directory use cloud-only identity — accounts exist only in Entra ID (Microsoft 365) or Google Workspace, with no on-premises sync. In cloud-only environments: accounts are created directly in the Microsoft 365 Admin Center or Google Admin Console; no sync infrastructure is needed; all authentication happens in the cloud. This is typical for small businesses, startups, and organizations that have never had on-premises infrastructure. The technician creates users directly in the admin portal rather than in Active Directory.

Section FLicensing Assignment

Cloud productivity services are licensed per user. Unlike traditional software where a license key unlocks a single installation, cloud licenses are assigned to user accounts — controlling which services and features each user can access. A user without a license cannot use the service, even if their account exists in the directory. Managing license assignment is a routine IT task that technicians in help desk and desktop support roles frequently perform.

License tiers
Microsoft 365 licenses come in tiers that bundle different services. Common tiers: Microsoft 365 Business Basic — web-only Office apps, Exchange Online, Teams, OneDrive, SharePoint; Microsoft 365 Business Standard — adds full desktop Office apps (Word, Excel, PowerPoint, Outlook) installable on 5 devices; Microsoft 365 Business Premium — adds Intune MDM, Defender for Business, Azure AD Premium P1; Microsoft 365 E3/E5 — enterprise tiers with advanced compliance, security, and voice features. A user who reports they cannot install Office desktop applications likely has Business Basic — they need at least Business Standard for desktop app access.
Assigning a license (per-user)
Microsoft 365 Admin Center (admin.microsoft.com) → Users → Active Users → click the user → Licenses and apps tab → check the license to assign → Save. The license activates within minutes. The user can then access the licensed services. When a license is removed, the user loses access to associated services (OneDrive files become read-only, Outlook can no longer send/receive after a grace period). License availability is shown at the top of the Billing → Licenses page — if all licenses are consumed, a new license must be purchased before it can be assigned to a new user.
Group-based licensing
In larger organizations, group-based licensing (a Microsoft Entra ID P1 feature) automates license assignment. A license is assigned to a security group in Entra ID — all members of the group automatically receive the license. When a user is added to or removed from the group, their license is automatically assigned or revoked. This eliminates the need to manually assign licenses to each new user — the onboarding process just requires adding the user to the appropriate group. Group-based licensing is managed in the Entra Admin Center → Groups → [group name] → Licenses.
Service plan management
Within a license, individual service plans (components) can be enabled or disabled per user. For example, a Microsoft 365 Business Standard license includes Exchange Online, Teams, SharePoint, OneDrive, and Office apps — but you can disable Teams for a specific user if the organization uses Zoom instead, while still allowing them access to all other services. In Admin Center → user → Licenses and apps → expand the license → toggle individual services on or off. This is useful when an organization has a licensing agreement that includes a service they don't want users to adopt, or when specific users have specialized roles that don't require certain tools.
Office app installation from license
Users with a license that includes desktop Office apps can install Office on up to 5 PCs/Macs and 5 mobile devices. Installation: user signs into portal.microsoft.com → click Install Office → Office 365 apps → the setup executable downloads and installs Click-to-Run Office. The installation activates automatically when the user signs in with their licensed Microsoft 365 account — no product key is required. If a user's license is removed or expires, Office enters a reduced functionality mode (read-only) after a grace period. A common help desk issue: "Office is asking me to activate" — usually means the license was removed, the account password changed invalidating the cached token, or the subscription has lapsed.
Google Workspace License Assignment
Managing licenses and service access in Google Admin Console
Google Workspace
Google Workspace tiers
Google Workspace tiers: Business Starter — 30 GB pooled storage, Meet up to 100 participants, basic security; Business Standard — 2 TB pooled, Meet up to 150 + recording, more admin controls; Business Plus — 5 TB pooled, eDiscovery and audit, 250-person Meet; Enterprise — unlimited storage, advanced security, DLP, data regions. Licenses are assigned per user; inactive users still consume a license if their account is active. Suspended accounts do not consume a license.
Assigning licenses in Google Admin
Google Admin Console (admin.google.com) → Users → click user → Licenses → assign the appropriate Workspace license. In Google Workspace, licenses are often assigned based on Organizational Units (OUs) — the admin assigns a license to all users in an OU, and any user added to that OU automatically receives the license. This is Google Workspace's equivalent of Microsoft's group-based licensing. Individual service access (Gmail, Drive, Meet, Chat) can also be toggled per OU or per user in Admin Console → Apps → Google Workspace → [Service] → turn on/off for selected OUs.
License reclamation
When an employee leaves the organization, their license should be reclaimed and reassigned. In both Microsoft 365 and Google Workspace: offboarding involves suspending or deleting the account. In Microsoft 365: the license is removed from the departing user and can be immediately assigned to a new user. In Google Workspace: suspending a user releases their license for reassignment. Before suspension/deletion, data should be transferred — in Google Admin, use Transfer ownership to move Drive files and Gmail data to a manager; in Microsoft 365, use the user offboarding wizard in Admin Center to assign a delegate to the mailbox and export data.

Section GNew User Onboarding — End-to-End Workflow

Understanding the full onboarding workflow — from account creation to a fully configured workstation with cloud productivity access — is what ties all the topics in this objective together. The following flow shows the complete sequence for provisioning a new user in a hybrid Microsoft 365 / Active Directory environment, which is the most common enterprise scenario.

New Employee Cloud Productivity Setup — Microsoft 365 Hybrid Environment
1. Create AD account
→
Create user in on-premises Active Directory (Active Directory Users and Computers). Set UPN (User Principal Name) matching the cloud domain (e.g., jdoe@company.com). Add to appropriate security groups (which map to license groups if group-based licensing is configured).
2. Entra ID Connect sync
→
Entra ID Connect automatically syncs the new account to Microsoft Entra ID within 30 minutes (or force-sync with Start-ADSyncSyncCycle -PolicyType Delta on the server). The account now appears in the Microsoft 365 Admin Center.
3. Assign license
→
In Microsoft 365 Admin Center → Users → Active Users → [user] → Licenses: assign the appropriate Microsoft 365 license (e.g., Business Standard). If group-based licensing is configured, this happens automatically when the user is added to the licensed group in step 1.
4. Configure email client
→
Open Outlook → enter email address → Autodiscover configures Exchange Online automatically. Modern authentication prompts for Microsoft 365 credentials and MFA if required. Verify mail flow: send and receive a test message.
5. Sign in to OneDrive
→
OneDrive opens automatically on first login for domain-joined Hybrid Azure AD joined machines. If not, click OneDrive in system tray → Sign in. Configure Files On-Demand and folder sync settings based on the user's storage needs and device capacity.
6. Install/sign in to Teams
→
Teams installs automatically with Microsoft 365 Apps or via Company Portal (Intune). Sign in with Microsoft 365 credentials. Configure audio/video devices in Settings → Devices. Add user to appropriate Teams and channels. Test a call or meeting.
7. Install Office apps (if licensed)
→
Office installs via Microsoft 365 Apps deployment (Intune/SCCM pushes it automatically) or user self-service at portal.microsoft.com → Install Office. Activation is automatic when the user signs into Office with their Microsoft 365 account.
8. Verify and document
→

Objective 1.11 — Key Facts Summary

Exchange OnlineMicrosoft 365 cloud email. Outlook uses Autodiscover for automatic setup. IMAP port 993, SMTP port 587. POP3 not recommended for cloud email.
Gmail / IMAPEnable IMAP in Gmail settings for third-party clients. App Password required when 2FA is on and client doesn't support OAuth. IMAP server: imap.gmail.com port 993.
OneDrive setupSign in via system tray cloud icon with Microsoft 365 credentials. Syncs to C:\Users\[user]\OneDrive - [Org]. Files On-Demand shows all files without downloading.
Files On-Demand iconsCloud = online only; sync arrows = syncing; green check = local copy available; solid green check = always keep on device.
OneDrive reset%localappdata%\Microsoft\OneDrive\onedrive.exe /reset — resets sync engine without deleting cloud files. Use for persistent sync errors.
SharePoint syncTeam/org storage behind Microsoft Teams. Sync to local via Drive for Desktop-equivalent OneDrive client: SharePoint library → Sync button. Appears in File Explorer.
Google Drive for DesktopStream mode = virtual drive letter, files download on demand. Mirror mode = selected folders fully downloaded for offline access.
Shared DrivesGoogle equivalent of SharePoint — org-owned, persists after employee departure. Appears in Drive for Desktop alongside My Drive.
Word vs. Google DocsBoth support real-time co-authoring. Word requires OneDrive/SharePoint for co-author + AutoSave. Docs saves every few seconds automatically in browser.
Excel Online limitationVBA macros do not run in Excel Online — requires full desktop Excel. Users with Business Basic license cannot install desktop Office apps.
Microsoft Teams setupInstall with M365 Apps or separate download. Sign in with M365 credentials. Configure audio/video in Settings → Devices. Stores files in SharePoint behind the scenes.
Google MeetNo install needed for browser. Link generated from Google Calendar event. Recordings saved to organizer's Drive → Meet Recordings (Business and above).
Camera not workingCheck OS privacy settings: Windows Settings → Privacy → Camera; macOS System Preferences → Security → Camera. App must be granted permission.
Entra ID ConnectSyncs on-prem Active Directory to Microsoft Entra ID (Azure AD). Runs on a Windows Server. Default sync interval: 30 minutes. Force sync: Start-ADSyncSyncCycle -PolicyType Delta.
Password Hash SyncRecommended auth mode for Entra ID Connect. Password hashes synced to cloud; authentication works even if on-prem is down. Alternative: Pass-Through Auth (requires on-prem availability).
GCDSGoogle Cloud Directory Sync — unidirectional sync from on-prem AD/LDAP to Google Workspace. AD is source of truth; Admin Console changes may be overwritten at next sync.
M365 license assignmentadmin.microsoft.com → Users → Active Users → user → Licenses and apps. License activates within minutes. No license = no service access.
Group-based licensingEntra ID P1 feature — assign a license to a security group; all members receive it automatically. Membership change = automatic license grant/removal. Managed in Entra Admin Center.
Service plan managementIndividual services within a license (Teams, Exchange, SharePoint) can be toggled on/off per user in Admin Center → user → Licenses and apps → expand license.
Office activation "reduced mode"Means license was removed, expired, or account token expired. Re-sign in to Office with M365 account to re-activate. No product key needed — license is account-based.

High-Probability Exam Scenarios

Scenario 1: A new user reports they can log in to Microsoft 365 online but cannot install Word or Excel on their computer. What is the most likely cause? → Their Microsoft 365 license does not include desktop Office apps — they likely have Business Basic (web-only). Upgrade their license to Business Standard or higher to enable desktop app installation.

Scenario 2: A user's OneDrive shows a red X on several files and they are not syncing. What should the technician check first? → File names — OneDrive cannot sync files with illegal characters in the name (: * ? < > | " /). Rename the affected files. Also check available OneDrive storage quota and that the user is signed in.

Scenario 3: A user's laptop has limited storage and they want to access all their OneDrive files without them taking up local disk space. What feature resolves this? → Enable OneDrive Files On-Demand. This shows all files in File Explorer without downloading them — files consume no local disk space until opened. Set rarely used folders to "online only" by right-clicking → Free up space.

Scenario 4: A new employee was created in Active Directory but their account does not appear in Microsoft 365 after 2 hours. What should the technician check? → The Entra ID Connect sync service on the on-premises server. Verify the service is running and trigger a manual delta sync: Start-ADSyncSyncCycle -PolicyType Delta in PowerShell on the Entra ID Connect server. Also verify the UPN suffix of the AD account matches the verified domain in Microsoft 365.

Scenario 5: A user cannot set up Gmail in Outlook and is seeing an authentication error. Their Google account uses 2-Step Verification. What is needed? → An App Password. When 2-Step Verification is enabled and the email client doesn't support OAuth, the user must generate an App Password in Google Account → Security → App Passwords and use that instead of their regular Google password in Outlook.

Scenario 6: A company uses Google Workspace and wants all employees in the "Sales" department to automatically get a Business Standard license when added to the department OU in Google Admin. What is the correct approach? → Assign the Google Workspace Business Standard license to the "Sales" organizational unit (OU) in Google Admin Console. Any user added to that OU will automatically receive the license.

Scenario 7: A remote employee reports their camera works in the operating system's camera app but not in Microsoft Teams. What should the technician check? → Windows privacy settings. Navigate to Settings → Privacy → Camera → verify that Microsoft Teams is listed and that the toggle is set to allow access. Teams needs explicit OS-level permission to use the camera, separate from the camera hardware working correctly.
