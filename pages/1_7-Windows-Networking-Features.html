OVERVIEWIntroduction

Objective 1.7 covers the client-side Windows configuration tasks that get a desktop or laptop properly connected to and functioning on a network — building directly on the networking fundamentals from the Core 1 exam's Domain 2 (IP addressing, subnet masks, gateways, connection types) but applying them specifically within the Windows operating system's settings, dialogs, and conventions.

This objective covers seven related areas: how a Windows machine identifies itself and shares resources on a network (domain vs. workgroup), the built-in firewall protecting that machine, the actual IP configuration values that make networking work, the different ways a Windows client can establish a network connection, proxy configuration, the public/private network distinction, navigating network resources through File Explorer, and managing data usage on metered connections.

Building on Core 1 Domain 2

Several concepts here — IP addressing, subnet masks, default gateways, static vs. dynamic addressing, VPN, wireless vs. wired — were already covered conceptually in Core 1 (objectives 2.6 and 2.7). Objective 1.7 asks you to apply that same knowledge specifically within Windows: where do you go to configure these settings, what do the relevant dialogs look like, and what Windows-specific terminology and behaviors apply on top of the underlying networking concepts you already know.

PART 1Domain Joined vs. Workgroup

Every Windows computer on a network belongs to one of two membership models, which fundamentally determines how user accounts, security policy, and resource sharing are managed.

DOMAIN JOINED
  • Authentication — Centralized via Active Directory on a domain controller
  • Account management — User accounts created/managed centrally by IT
  • Policy — Group Policy pushes consistent settings to all domain machines
  • Scale — Designed for many computers (business/enterprise networks)
  • Sign-in — Same domain credentials work on any domain-joined machine
WORKGROUP
  • Authentication — Decentralized; each computer manages its own local accounts
  • Account management — No central administration; configured machine by machine
  • Policy — No centralized policy enforcement; local settings only
  • Scale — Designed for small numbers of computers (home/small office)
  • Sign-in — Each machine requires its own separately-created local account

Exam Angle

A scenario describing a large business environment, centralized password policy, or IT being able to push the same settings to hundreds of machines at once points to a domain. A scenario describing a home network or very small office where each computer is configured individually, with no central server managing accounts, points to a workgroup. This distinction underpins how shared resources (below) are typically accessed and authenticated.

Shared Resources

Whether domain-joined or in a workgroup, Windows clients commonly access several categories of network-shared resources.

Printers A printer shared from another computer or made available directly on the network (objective 2.5/3.7 concepts) appears as an installable network printer in Windows, allowing multiple users to print to the same physical device.
File servers A dedicated server (or a shared folder on another computer) hosting files accessible to network users, typically via the SMB protocol (objective 2.1/2.3) — the underlying mechanism behind virtually all Windows file sharing.
Mapped drives A network share assigned a drive letter (e.g., Z:) in Windows, making it appear and behave like a local drive in File Explorer and within applications, rather than requiring the full network path to be typed out every time.

PART 2Local OS Firewall Settings

Windows includes a built-in host-based firewall (Windows Defender Firewall), conceptually the same type of "software/host-based firewall" introduced in objective 2.3, filtering traffic to and from the local machine specifically — distinct from a network-level hardware firewall sitting at the network perimeter.

Application Restrictions and Exceptions

The Windows firewall can allow or block specific applications from communicating over the network, either entirely or only on specific network profile types (private vs. public, discussed in Part 6). An exception (or "allowed app") is a rule permitting a specific application through the firewall that would otherwise be blocked by default — commonly needed when installing software that requires inbound network connections, such as a file-sharing application, a remote access tool, or certain games/collaboration software.

Configuration

Windows Firewall configuration is accessible through both a simplified Control Panel interface (basic on/off toggles per network profile, and a list of allowed apps) and the more advanced Windows Defender Firewall with Advanced Security console, which allows granular inbound/outbound rules based on specific ports, protocols, IP address ranges, and programs — mirroring the general firewall rule concepts from objective 2.5, but applied at the individual host level.

Exam Angle

A scenario describing a newly installed application that "can't be reached by other computers on the network" or "won't accept incoming connections" often points to the Windows Firewall blocking that application by default — the fix is adding an appropriate exception/allowed-app rule, rather than assuming a deeper network or hardware fault.

PART 3Client Network Configuration

This section applies the IP addressing concepts from Core 1 objective 2.6 directly within Windows' network adapter settings (accessible via Network and Sharing Center, or the modern Settings app's Network & Internet section).

IP addressing scheme The actual IPv4 (and/or IPv6) address assigned to the network adapter — either entered manually (static) or received automatically via DHCP (dynamic), as covered conceptually in objective 2.6.
DNS settings The DNS server address(es) the client uses to resolve domain names to IP addresses (objective 2.1/2.3). Windows can use DNS servers automatically provided by DHCP, or a technician can manually specify preferred/alternate DNS servers — common troubleshooting steps include switching to a known-reliable public DNS server when name resolution problems are suspected.
Subnet mask Defines the network/host boundary for the assigned IP address, exactly as covered in objective 2.6 — almost always 255.255.255.0 in typical small networks, configured automatically via DHCP or manually alongside a static IP.
Gateway The default gateway address (objective 2.6) — the router's address that the Windows client sends to for any traffic destined outside the local subnet, including all internet-bound traffic.
Static vs. dynamic Whether the IP configuration is manually entered (static) or automatically obtained via DHCP (dynamic) — in Windows, this is the literal toggle between "Obtain an IP address automatically" and "Use the following IP address" in the adapter's IPv4 properties dialog.

Where This Lives in Windows

The classic path to manually configure these settings: Control Panel → Network and Sharing Center → Change adapter settings → right-click the adapter → Properties → Internet Protocol Version 4 (TCP/IPv4) → Properties. This single dialog is where static/dynamic, IP address, subnet mask, default gateway, and DNS servers are all configured together — recognizing this dialog and its fields is directly testable.

PART 4Establish Network Connections

Windows supports establishing network connectivity through several distinct methods, each configured through its own settings area.

VPN A Virtual Private Network connection creates an encrypted tunnel over an existing internet connection, allowing a remote client to securely access a private network (such as a corporate network) as if directly connected to it. Configured in Windows via Settings → Network & Internet → VPN, requiring a server address, VPN protocol/type, and authentication credentials.
Wireless Standard Wi-Fi connectivity (objective 2.5/2.7 concepts), configured by selecting an available SSID and entering the appropriate security credentials through Windows' network/Wi-Fi settings.
Wired A direct Ethernet connection, which Windows typically detects and configures automatically (often via DHCP) the moment a cable is connected, requiring no manual network selection the way Wi-Fi does.
WWAN/cellular Wireless Wide Area Network connectivity, used by laptops with a built-in cellular modem (or a connected cellular hotspot device/dongle) to access the internet via the cellular network directly, conceptually similar to the cellular data concepts covered in objective 1.3 but applied to a Windows laptop rather than a phone.

Exam Angle

Recognize that VPN is fundamentally different from the other three — wireless, wired, and WWAN are all ways of getting any internet/network connectivity in the first place, while VPN is layered on top of an already-existing connection to securely reach a separate private network. A laptop could be connected via Wi-Fi (the underlying connection) and then additionally connect a VPN (the secure tunnel running over that Wi-Fi connection) to reach corporate resources.

PART 5Proxy Settings

As introduced conceptually in objective 2.3, a proxy server acts as an intermediary between a client and the internet. In Windows, proxy settings (Settings → Network & Internet → Proxy) tell the operating system to route web/application traffic through a specified proxy server rather than connecting directly to destinations.

  • Manual proxy setup — a technician enters a specific proxy server address and port directly, often required in business environments enforcing content filtering or traffic monitoring through a forward proxy.
  • Automatic proxy setup — Windows can be configured to automatically detect proxy settings, or to use a proxy auto-configuration (PAC) script/URL that defines proxy rules programmatically, common in larger managed environments.
  • Bypass for local addresses — proxy configurations typically allow specifying that local/internal network addresses should bypass the proxy entirely, since proxying is generally only relevant/necessary for external internet-bound traffic.

Common Pitfall

A misconfigured or stale proxy setting is a classic, often-overlooked cause of "internet doesn't work, but the network connection itself appears fine" — particularly after a laptop moves from a work environment requiring a specific proxy to a home network where that proxy server is unreachable. Checking proxy settings should be part of standard internet-connectivity troubleshooting, especially for laptops that move between different networks.

PART 6Public Network vs. Private Network

When Windows connects to a new network for the first time, it prompts the user to classify that network — a setting that directly controls firewall behavior and network discoverability, independent of the actual technical connection type (Wi-Fi vs. Ethernet).

Network ProfileTypical UseBehavior
Private networkHome or trusted work networkNetwork discovery enabled; the PC is visible to and can discover other devices on the network (for file/printer sharing); firewall rules are more permissive
Public networkCoffee shops, airports, hotels, any untrusted/shared networkNetwork discovery disabled; the PC is hidden from other devices on the network; firewall rules are more restrictive by default, reducing exposure to other (potentially hostile) devices sharing the same network

Exam Angle

A scenario describing a user unable to see or share files with other computers on what should be a trusted home/office network often points to that network being incorrectly classified as public in Windows, suppressing network discovery and applying stricter firewall rules. The fix is reclassifying the network connection as private through Windows network settings. Conversely, a laptop connecting to public Wi-Fi at a coffee shop should remain classified as public to minimize exposure to other untrusted devices on that same network.

PART 7File Explorer Navigation — Network Paths

Beyond mapped drives (Part 1), Windows allows direct navigation to network resources using a UNC (Universal Naming Convention) path, typed directly into File Explorer's address bar.

\\SERVERNAME\ShareName
\\192.168.1.50\Documents

A UNC path always follows the same format: two backslashes, then the server's name (or its IP address), then a single backslash, then the specific share name being accessed. This is the standard way of referencing a network resource directly without first mapping it to a drive letter — useful for one-off access to a share, or in scripts/shortcuts referencing a network location precisely.

UNC Path vs. Mapped Drive

A mapped drive is essentially a saved shortcut to a specific UNC path, displayed with its own drive letter for convenience and persistence across sessions. A UNC path typed directly works immediately for one-time or occasional access without creating any persistent drive mapping at all. Both ultimately reach the exact same underlying network share — the difference is purely about convenience and persistence, not the underlying technology.

PART 8Metered Connections and Limitations

Windows allows a network connection (most commonly Wi-Fi, but also applicable to WWAN/cellular connections) to be marked as a metered connection, signaling to the operating system and installed applications that data usage on this connection is limited or costly, directly paralleling the data cap awareness concepts introduced for mobile devices in objective 1.3.

  • Reduced background data usage — Windows and many applications automatically reduce or pause background data-consuming activity (automatic updates, background app syncing, cloud storage syncing) on a connection marked as metered.
  • Windows Update behavior — large OS updates may be deferred or require manual confirmation on a metered connection, rather than downloading automatically as they typically would otherwise.
  • Manual configuration — a technician or user can manually mark any Wi-Fi network as metered through Windows network settings, useful when connected to a mobile hotspot or a connection with a known limited data allowance.

Exam Angle

A scenario describing a user tethered to a phone's hotspot (objective 1.2/1.3) who wants to prevent Windows from consuming large amounts of cellular data through automatic updates and background syncing should mark that Wi-Fi connection as metered in Windows settings — directly mirroring the mobile-device "restrict large syncs to Wi-Fi only" logic from objective 1.3, just from the opposite direction (limiting a Windows PC's usage of a cellular-backed connection).

REFERENCE1.7 Quick Reference

Domain vs. Workgroup By Scenario

  • Large business, centralized IT control → Domain
  • Home/small office, independent machines → Workgroup

Common Symptom → Likely Setting

  • App can't accept inbound connections → Firewall exception needed
  • Can't see other PCs on a trusted network → Network set to Public, should be Private
  • Internet broken after leaving the office → Stale proxy settings
  • Burning cellular hotspot data fast → Mark connection as metered

Accessing a Network Share

  • One-time access → Type a UNC path directly
  • Frequent/ongoing access → Create a mapped drive

Connection Types

  • Underlying connectivity → Wired, wireless, or WWAN
  • Secure tunnel on top of any of those → VPN

Final Exam Reminders

Domain = centralized AD authentication/policy, enterprise scale. Workgroup = decentralized, per-machine accounts, home/small office scale.

IPv4 Properties dialog = the single place static/dynamic addressing, IP, subnet mask, gateway, and DNS are all configured together in classic Windows networking.

VPN = a secure tunnel layered on top of an existing wired/wireless/WWAN connection, not a connection type on its own.

Public network = hidden, restrictive firewall, for untrusted networks. Private network = discoverable, permissive firewall, for trusted networks.

UNC path (\\server\share) = direct network access without mapping. Mapped drive = a persistent, convenient shortcut to the same kind of path.

Metered connection = reduces background data use and defers large updates, directly relevant when tethered to a cellular hotspot.
