OVERVIEWIntroduction to PC Security Symptoms

Malware infections and other security compromises rarely announce themselves cleanly. Instead, they surface as a collection of symptoms — a slow browser, a strange pop-up, a file that's suddenly missing, a network connection that stops working — that overlap heavily with ordinary hardware or software problems. Objective 3.4 is about pattern recognition: learning to read a cluster of symptoms and recognize when the underlying cause is a security issue rather than a routine glitch, so the correct response (isolate, investigate, remediate) happens instead of a wasted hour chasing the wrong fix.

This objective splits into two symptom groups. The first is system-level symptoms — the signs a compromised or misconfigured system shows at the OS layer: network access problems, desktop alerts, fake antivirus warnings, altered or missing files, unwanted notifications, and failed OS updates. The second is browser-related symptoms — the signs that show up specifically inside a web browser: pop-ups, certificate warnings, redirection, and degraded performance. Many real infections produce symptoms from both groups simultaneously, and the exam expects you to connect the dots across both.

Core Concept — Symptom Clusters, Not Single Symptoms

A single odd symptom — one pop-up, one slow page load — is rarely enough to diagnose a security issue on its own; each individual symptom in this objective has a plausible non-malicious explanation too. What separates a security incident from routine flakiness is the cluster: several of these symptoms appearing together, appearing suddenly, or appearing right after a risky action (clicking a link, installing something, plugging in an unknown drive). Objective 3.4 tests your ability to recognize that pattern and to know, symptom by symptom, what it typically indicates and what the next diagnostic step should be.

SECTION 1Common System-Level Symptoms

These symptoms appear at the operating system level rather than inside any one application. They are frequently the first visible sign a user notices and reports to the help desk, well before any deeper investigation confirms a security cause.

Unable to Access the Network

A machine that suddenly can't reach the network — while other devices on the same network function normally — is a classic sign of malware interfering with network connectivity. Malware frequently blocks network access deliberately, either to prevent the user from downloading removal tools and updated antivirus definitions, or as a side effect of the malware hijacking network settings for its own command-and-control traffic.

Unable to Access the NetworkInvestigate first
Typical malicious cause Malware modifying the hosts file, DNS settings, or proxy configuration to block legitimate traffic (especially to antivirus/update sites) while still allowing its own malicious traffic through
Non-malicious alternatives Failed NIC driver, disabled adapter, incorrect IP configuration, DHCP failure, unplugged/failed cable, or a legitimate firewall/VPN client misconfiguration — always rule these out first before assuming malware
Where to check Inspect the hosts file for unauthorized entries, review proxy settings in browser/OS network settings, and check DNS server addresses for unexpected values pointing to unfamiliar servers

Desktop Alerts

Desktop alerts are unexpected pop-up windows or notification balloons that appear directly on the desktop, outside of any browser, often claiming urgent problems ("Your computer is infected," "Your license has expired," "Click here to renew protection"). Legitimate security software does generate real alerts, but malware and adware are also extremely effective at mimicking that exact visual style to manipulate a user into clicking, calling a fake support number, or installing additional malicious software.

False Alerts Regarding Antivirus Protection

A false antivirus alert (sometimes called "scareware" or "rogueware") is a fraudulent warning designed to look like a legitimate antivirus product, claiming the system is infected with a long list of alarming threats and pressuring the user to pay for a "full version" or call a phone number to "fix" the problem. This is one of the most common and effective social engineering tactics in circulation, because it exploits the user's fear and unfamiliarity with what their real antivirus software actually looks like.

Signs of a Fake AV Alert

  • Wrong branding — doesn't match the antivirus product actually installed on the machine
  • Urgency and fear tactics — countdown timers, alarming red graphics, exaggerated threat counts
  • Demands payment or a phone call — legitimate AV renewal flows rarely require calling a number
  • Appears in the browser as a full-screen takeover — often impossible to close normally, sometimes locking the keyboard/mouse
  • Can't be dismissed with the normal close button — may require Task Manager or a forced browser close

Correct Response

  • Never call the number or click anything inside the alert — treat it as hostile content
  • Close via Task Manager rather than clicking any button inside the alert window
  • Run a scan with the legitimate, already-installed antivirus to check for an actual infection that triggered the popup
  • Check installed programs and browser extensions for anything unfamiliar that may have caused it
  • Educate the end user on what their real AV alerts look like, per the 2.6 malware removal procedure

Altered System or Personal Files

Malware — particularly ransomware, but also more subtle data-theft tools — frequently modifies, renames, encrypts, hides, or deletes files as part of its operation. This objective calls out two specific symptoms under this heading.

Missing/renamed files Files that a user expects to find are simply gone, or appear under unfamiliar names/extensions. Ransomware is the classic cause — it encrypts files and appends a new extension (e.g., .locked, .encrypted) while the original files effectively "disappear." Some malware also deletes or moves files to hide its own presence or to disrupt backups and shadow copies.
Inability to access files Files still exist but can no longer be opened — commonly because ransomware has encrypted them and only a decryption key (held by the attacker) can restore access, or because malware has altered file/folder permissions to block the user's own account from reading its own data.

Ransomware Note — Preserve Evidence, Don't Panic-Delete

If altered/inaccessible files point to ransomware, the immediate priority is to disconnect the machine from the network to stop further spread (Objective 2.6's quarantine step) without powering it off, since powering off can complicate recovery in some cases and forensic review. Do not pay a ransom, and do not assume renaming files back or deleting the ransom note fixes anything — the underlying encryption remains. Recovery depends on clean backups (Objective 4.3) or, in rare cases, a published decryption tool for that specific ransomware family.

Unwanted Notifications Within the OS

Beyond desktop alerts and fake AV pop-ups, malware and adware frequently register themselves as legitimate-looking notification sources within the OS's own notification system (e.g., Windows Action Center), generating a steady stream of ads, "system optimization" prompts, or requests to install additional software. Because these come through the OS's own notification channel, users often trust them more than an obvious browser pop-up, making this a particularly effective vector for further compromise.

OS Updates Failures

Legitimate Windows/OS updates repeatedly failing to install — especially if this starts suddenly on a previously healthy machine — can indicate malware is deliberately blocking the update service to keep the system vulnerable to a specific unpatched exploit, or has disabled/corrupted the update service itself. It can also point to disk corruption, insufficient disk space, or a genuinely corrupted update component, so this symptom always needs to be correlated with others before concluding malware is the cause.

Malicious cause Malware disabling the Windows Update service, blocking access to Microsoft's update servers via hosts file/firewall rule changes, or corrupting update-related system files to intentionally keep the system unpatched and exploitable.
Non-malicious causes Corrupted Windows Update components, insufficient free disk space, a stuck update in the queue, third-party software conflicts, or a genuinely buggy update — resolved with the built-in Windows Update Troubleshooter, DISM, or sfc /scannow (see Objective 1.4/1.5 tools).

SECTION 2Browser-Related Symptoms

Because the browser is the most common point of contact between a user and the internet, it is also the most common place security symptoms first appear. These four browser-specific symptoms are heavily tested because they map directly to distinct underlying causes — and distinct fixes.

Random/Frequent Pop-Ups

Persistent pop-up windows or new tabs opening on their own — especially ones that appear even when not actively browsing, or that appear across many different, unrelated websites — almost always point to adware or a malicious/rogue browser extension rather than any single website being at fault. Legitimate websites occasionally use pop-ups for genuine functionality, but a pattern across every site visited is the tell.

Likely Causes

  • Adware — a Potentially Unwanted Program (PUP) bundled with other software installs, generating ad pop-ups for revenue
  • Malicious browser extension — installed deliberately or bundled silently with other software
  • Browser hijacker — modifies browser settings/homepage and injects ads/pop-ups system-wide

Remediation Steps

  • Review installed extensions/plug-ins and remove anything unfamiliar or unused (Objective 2.11)
  • Check installed programs list for bundled adware installed alongside legitimate software
  • Enable the browser's built-in pop-up blocker if it was disabled
  • Run a full anti-malware scan if the pattern persists after cleaning extensions

Certificate Warnings

A certificate warning appears when the browser cannot validate that the site's HTTPS/TLS certificate is legitimate — the certificate may be expired, self-signed, issued for a different domain name, or not trusted by a recognized Certificate Authority. While many certificate warnings are simply the result of an expired cert on an otherwise legitimate site (a routine, non-malicious problem), a certificate warning can also indicate a genuine security threat.

Routine/non-malicious cause The website's own TLS certificate has expired or was misconfigured by its administrator; this is extremely common and usually resolves once the site owner renews the certificate.
On-path (man-in-the-middle) attack An attacker intercepting traffic between the user and a legitimate site, presenting their own certificate in place of the real one in order to decrypt or manipulate the traffic in transit. The browser flags the mismatch because the certificate doesn't match what it expects for that domain.
DNS/host manipulation Malware-altered DNS settings or a poisoned hosts file redirecting the user to a fraudulent look-alike site that cannot present a valid certificate for the domain the user actually typed, since it doesn't control that real domain.

Exam Angle — Never "Click Through" a Certificate Warning to Sensitive Sites

The correct technician guidance is never to instruct a user to simply bypass or "click through" a certificate warning on a banking, email, or other sensitive login site — doing so may hand credentials directly to an attacker positioned in the middle of the connection. Investigate the cause (check the date/time on the system, check DNS settings, check for other symptoms of compromise) before assuming it's just an expired cert.

Redirection

Redirection occurs when typing in one URL, or clicking a legitimate search result, lands the user on a completely different, often unrelated or malicious site. This is one of the clearest browser-level signs of a compromise, because it means something between the user's input and the destination is actively intercepting and rewriting the request.

CauseMechanismFix Location
Hosts file hijackMalware adds entries to the local hosts file, mapping legitimate domain names to malicious IP addressesEdit/reset %SystemRoot%\System32\drivers\etc\hosts

Degraded Browser Performance

A browser that has become noticeably slow — long page load times, unresponsive tabs, high CPU/memory usage attributed to the browser process — can result from ordinary causes like too many open tabs or an outdated browser version, but it is also a common symptom of malicious background activity riding along with normal browsing: a cryptominer running in a background tab or extension, adware injecting content into every page, or spyware quietly exfiltrating browsing data in the background.

Non-Malicious Causes

  • Too many open tabs consuming available RAM
  • Outdated browser version missing performance improvements
  • Excess legitimate extensions each adding overhead
  • Full/corrupted cache slowing page rendering
  • Insufficient system RAM for the workload generally

Malicious Causes

  • Cryptominer — browser-based or system-level, consuming CPU in the background
  • Adware injecting content into every page load, adding rendering overhead
  • Spyware/keylogger running alongside the browser, consuming resources while monitoring activity
  • Malicious extension performing unwanted background network activity

Quick Diagnostic — Task Manager Before Anti-Malware

Before running a full anti-malware scan for degraded browser performance, open Task Manager and check the browser process's CPU and network usage while no tabs are actively loading anything. Persistent high CPU with no user activity — especially spiking together across multiple browser subprocesses — is a strong indicator of a cryptominer or other background malicious process riding inside the browser, and narrows the investigation before a full scan is even run.

SECTION 3General Diagnostic Approach

Objective 3.4 is a symptom-recognition objective, but the exam also expects you to connect these symptoms back to the broader malware removal process from Objective 2.6. Once a security cause is suspected, the same overall workflow applies regardless of which specific symptom triggered the investigation.

Applying the 2.6 Malware Removal Workflow to a 3.4 Symptom
01
Investigate and verify. Confirm the symptom is real and reproducible, and look for additional symptoms from this objective that might be occurring alongside it — a single symptom in isolation is weaker evidence than a cluster.
02
Quarantine. Disconnect the affected machine from the network if malware is suspected, to prevent further spread or continued data exfiltration/command-and-control communication.
03
Disable System Restore (Windows Home) so a compromised restore point isn't used later and so restore points don't preserve the infection.
04
Remediate. Update anti-malware definitions, then scan and remove using safe mode or a preinstallation environment if the malware interferes with normal scanning.
05
Reimage/reinstall if necessary, schedule ongoing scans, re-enable System Restore with a fresh clean restore point, and educate the end user on what triggered the incident so it isn't repeated.

Why Symptom Recognition Matters Before Remediation

Jumping straight to a full malware scan every time a user reports a slow browser or a certificate warning wastes time when the actual cause is a non-malicious one — an expired certificate, too many open tabs, a failed Windows Update component. Objective 3.4 exists precisely so a technician can quickly triage which explanation is more likely based on the specific symptom and its context, and escalate to the full 2.6 workflow only once a security cause is genuinely indicated.

Symptom → Likely Malicious Cause

  • No network access, others fine — hosts file/DNS/proxy hijack
  • Files renamed/missing — ransomware encryption
  • Fake AV pop-up demanding payment — scareware/rogueware
  • Redirected to wrong site — hosts file, proxy, or DNS hijack
  • Browser slow, high CPU idle — cryptominer or spyware

Symptom → Likely Non-Malicious Cause

  • Certificate warning on one known site — expired cert, admin oversight
  • OS update fails repeatedly — corrupted update component, low disk space
  • Browser sluggish with 40 tabs open — insufficient RAM, not malware
  • Occasional single pop-up on one site — that site's own ad behavior
  • No network access, other devices also down — router/ISP outage

First Diagnostic Move by Symptom

  • Network access issue — check hosts file, DNS settings, proxy config
  • Fake AV alert — close via Task Manager, scan with real installed AV
  • Redirection/pop-ups — review installed extensions and programs list
  • Certificate warning — check system date/time, then DNS settings
  • Degraded browser performance — check Task Manager CPU/network usage

Escalation Trigger — Move to Full 2.6 Workflow

  • Two or more symptoms present together, especially across both system and browser categories
  • Files encrypted/renamed with unfamiliar extensions — treat as ransomware immediately
  • Symptom appeared right after a risky action (unknown download, link, attachment)
  • Confirmed unauthorized hosts file, DNS, or proxy changes found during investigation

Final Exam Reminders

A false antivirus alert should be closed via Task Manager, never by clicking any button inside the alert itself — clicking "Cancel," "Close," or the X can still trigger the malicious action the popup is designed to perform.

Missing/renamed files with new extensions is the signature symptom of ransomware. The correct first response is disconnecting from the network, not attempting to pay or rename files back.

Certificate warnings are not automatically malicious — an expired cert on a legitimate site is common and routine — but a certificate warning combined with other symptoms (redirection, DNS changes) should be treated as a potential on-path attack, and users should never be told to click through on sensitive login sites.

Redirection almost always traces back to the hosts file, DNS settings, proxy configuration, or a malicious extension — check these four locations in that order when troubleshooting.

Random pop-ups across many different, unrelated websites point to adware or a malicious extension on the machine itself, not to any single website being compromised.

Degraded browser performance with no active tabs loading anything, but sustained high CPU usage, points toward a cryptominer riding in a background tab, extension, or separate malicious process.

OS update failures and network access problems both deserve a non-malicious explanation check first (corrupted update components, disk space, cabling, DHCP) before malware is assumed, since both have very common innocent causes.

Symptom clusters are stronger evidence than any single symptom — the exam favors scenario questions describing two or three symptoms together specifically so you weigh the pattern, not just one isolated data point.
