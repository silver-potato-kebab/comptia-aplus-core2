OVERVIEWIntroduction

The Windows command line is an indispensable tool for IT support technicians. Many diagnostic and repair operations are faster, more precise, and sometimes only possible from a command prompt. When a system is unbootable, when a graphical tool fails to load, or when automating tasks via scripts, command-line proficiency is not optional — it is a core competency.

Objective 1.5 tests 22 specific commands organized into six functional categories: navigation, networking, disk management, file management, system information, and OS management. For each command, the exam expects you to know its purpose, its key switches, and — critically — which command to use in a given scenario. A scenario might describe a network problem, a corrupt disk, a group policy issue, or a need to create a directory structure; you must identify the correct tool.

Opening a Command Prompt

Three ways to open an elevated (administrator) command prompt: (1) Win + X → Windows Terminal (Admin) or Command Prompt (Admin). (2) Search → type "cmd" → right-click → Run as administrator. (3) Win + R → type cmd → Ctrl + Shift + Enter (runs with elevation). Many commands in this objective require elevation — always run as administrator when in doubt. In Windows 11, "Command Prompt" in the Win+X menu has been replaced by "Terminal."

The /? Switch — Built-In Help for Every Command

Every command covered in this objective supports the /? switch, which displays the command's syntax, all available switches, and usage examples directly in the terminal. This is explicitly tested on the exam. When you cannot remember a switch, type command /? before anything else. Example: ipconfig /?, chkdsk /?, robocopy /?. The help output is comprehensive and formatted clearly.

SECTION 1Navigation

Navigation Commands

Navigation commands allow a technician to move through the file system, list directory contents, and orient themselves within the directory tree. These are foundational — every command-line session begins with knowing where you are and being able to move to where you need to be.

cd — Change Directory

The cd command (short for change directory) moves the command prompt's working directory to a specified location. All subsequent commands without explicit paths operate relative to this working directory. It is the single most frequently used navigation command.

Syntax cd
cd [path]     chdir [path]    (cd and chdir are identical)
C:\> cd Windows — move into C:\Windows (relative path)
C:\Windows> cd C:\Users\Mike\Documents — jump to absolute path
C:\Users\Mike\Documents> cd .. — move up one directory level to C:\Users\Mike
C:\Users\Mike> cd ..\.. — move up two levels to C:\
C:\Users\Mike> cd \ — jump to root of current drive (C:\)
C:\> cd — typed alone, prints the current working directory path
Key Concepts
..Parent directory shortcut. cd .. always moves one level up. Can be chained: cd ..\..
\Root of the current drive. cd \ goes to C:\ (or D:\, etc.) regardless of depth.
Absolute pathStarts with a drive letter: C:\Windows\System32. Goes directly to that location from anywhere.
Relative pathNo drive letter. Navigates relative to current directory. cd System32 from C:\Windows goes to C:\Windows\System32.
Spaces in pathsWrap paths containing spaces in double quotes: cd "C:\Program Files\Mozilla Firefox"
/D switchcd /D D:\Folder — changes both the drive and the directory simultaneously. Without /D, cd D:\ changes directory but does not switch the active drive.

dir — Directory Listing

The dir command lists the contents of a directory — file names, subdirectory names, file sizes, and modification dates. It is the command-line equivalent of opening a folder in File Explorer and is essential for verifying that files exist, checking modification times, and finding files by pattern.

Syntax dir
dir [path\pattern] [switches]
C:\> dir — list all files and folders in current directory
C:\> dir C:\Windows\System32 — list contents of a specific path
C:\> dir *.exe — list only .exe files in current directory
C:\> dir /a — show ALL files including hidden and system files
C:\> dir /s *.log — search recursively for all .log files in all subdirectories
C:\> dir /p — pause output after each screenful (prevents scrolling past results)
C:\> dir /o:s — sort output by file size (smallest first)
Key Switches
/aShow all files including hidden (H) and system (S) files. Can be combined: /ah = hidden only, /as = system only.
/sSubdirectories — recursive listing. Searches the specified directory and all directories below it. Combine with a wildcard to search the entire drive: dir /s *.txt
/pPause — halts after each screen of output. Press any key to continue. Essential when listing directories with hundreds of entries.
/wWide format — displays file names across the width of the screen in columns, sacrificing date/size detail for compactness.
/o:[sort]Sort order: /o:n = name, /o:s = size, /o:d = date, /o:e = extension. Add - to reverse: /o:-s = largest first.
Wildcards* = any characters, ? = single character. *.exe = all executables, report?.txt = report1.txt, report2.txt, etc.

SECTION 2Network Commands

Network Commands

Network commands diagnose connectivity problems, query DNS, inspect active connections, map network drives, and trace the path packets take to a destination. These are among the most frequently tested commands on the A+ exam because network troubleshooting is a daily activity in IT support. The standard network troubleshooting sequence — from most basic to most advanced — is: ipconfig → ping → tracert / pathping → netstat → nslookup.

ipconfig — IP Configuration

ipconfig displays and manages the TCP/IP configuration of all network adapters on the local machine. It is the first command run in virtually any network troubleshooting scenario — verifying that the machine has a valid IP address, subnet mask, default gateway, and DNS server addresses.

Syntax ipconfig
ipconfig [switch]
C:\> ipconfig — summary: IP, subnet mask, default gateway for each adapter
C:\> ipconfig /all — full detail: MAC, DHCP server, DNS servers, lease times
C:\> ipconfig /release — release (surrender) the DHCP-assigned IP address
C:\> ipconfig /renew — request a new IP address from the DHCP server
C:\> ipconfig /flushdns — clear the local DNS resolver cache
C:\> ipconfig /displaydns — show all entries currently in the DNS cache
Key Switches & Diagnostic Interpretation
/allThe most useful switch. Shows Physical Address (MAC), DHCP Enabled/Disabled, DHCP server IP, DNS servers, lease obtained/expires times, and IPv6 addresses.
/release + /renewThe standard DHCP troubleshooting sequence. Release surrenders the current lease; renew requests a fresh IP from the DHCP server. Use when a device has no IP or a stale/conflicting address.
/flushdnsMost exam-tested switch. Clears the DNS resolver cache — the local table of recently resolved hostnames. Use when DNS changes have been made (new DNS record, domain migration) but the machine still resolves an old IP. Requires elevation on Windows 8+.
APIPA addressAn IP of 169.254.x.x with subnet mask 255.255.0.0 means the machine could not reach a DHCP server and self-assigned an Automatic Private IP Address. The machine cannot communicate beyond the local subnet. Check the physical connection and DHCP server availability.

Exam Focus — ipconfig /flushdns

A user reports they cannot access a website that was recently moved to a new server, even though other users on different machines can access it fine. The fix is ipconfig /flushdns — their DNS cache has the old IP address cached. This is one of the highest-probability ipconfig scenarios on the exam.

ping — Packet Internet Groper

ping sends ICMP Echo Request packets to a target host and measures whether a response is received and how long it takes. It is the most fundamental network connectivity test — confirming whether a host is reachable at the IP layer. Ping does not test application-layer connectivity (a host can respond to ping but have a web server that is down), but a failed ping confirms a fundamental connectivity problem.

Syntax ping
ping [switches] target_name_or_IP
C:\> ping google.com — ping by hostname (tests DNS resolution AND connectivity)
C:\> ping 8.8.8.8 — ping by IP (tests connectivity only, skips DNS)
C:\> ping 127.0.0.1 — ping loopback: tests local TCP/IP stack (does not leave the machine)
C:\> ping 192.168.1.1 — ping the default gateway: tests local network segment
C:\> ping -t 8.8.8.8 — continuous ping until Ctrl+C (monitor stability)
C:\> ping -n 20 8.8.8.8 — send 20 packets instead of the default 4
C:\> ping -l 1400 8.8.8.8 — send 1400-byte packets (test MTU/fragmentation)
Troubleshooting Methodology with Ping
Step 1: 127.0.0.1Ping loopback. If this fails, TCP/IP is not functioning on this machine — reinstall the network protocol stack.
Step 2: Own IPPing the machine's own IP address. If loopback succeeds but this fails, the NIC or driver has a problem.
Step 3: Default gatewayPing the router/gateway IP. If this fails, the machine cannot reach the local network — check cable, switch, or wireless connection.
Step 4: Remote IPPing a known external IP (8.8.8.8). If this fails but gateway ping succeeds, the router is not forwarding traffic to the internet.
Step 5: HostnamePing a hostname (google.com). If IP ping succeeds but hostname ping fails, DNS is not resolving — check DNS server settings.
Request Timed OutPackets sent but no response received. The host may be unreachable, a firewall may be blocking ICMP, or the host may have ICMP responses disabled.

netstat — Network Statistics

netstat displays active network connections, listening ports, protocol statistics, and the routing table. It answers the question: "what network connections does this machine currently have open, and what is listening for inbound connections?" It is an essential tool for identifying unexpected outbound connections from malware and verifying that a service is listening on the expected port.

Syntax netstat
netstat [switches] [interval]
C:\> netstat — show active TCP connections (no listening ports)
C:\> netstat -a — all connections AND listening ports (TCP + UDP)
C:\> netstat -b — show the executable (process) responsible for each connection
C:\> netstat -n — show IP addresses and port numbers numerically (skip DNS resolution)
C:\> netstat -ano — all connections, numeric, with PID — most useful for security analysis
C:\> netstat -r — display the routing table (same as "route print")
C:\> netstat -ano 5 — refresh every 5 seconds automatically
Key Switches & States
-anoThe most useful combination. -a = all connections/ports, -n = numeric (fast, no DNS lookup), -o = show PID. Use the PID with Task Manager → Details tab to identify the owning process.
-bShows the executable name responsible for each connection. Requires administrator privileges. Useful for identifying which program opened a suspicious connection.
ESTABLISHEDAn active, open connection. Data is flowing or has flowed recently.
LISTENINGA port is open and waiting for inbound connections. Services listening on unexpected ports warrant investigation.
TIME_WAITConnection is closed but the OS is waiting to ensure all packets have been received before fully releasing the port.
CLOSE_WAITRemote end has closed the connection; local end has not yet closed its side. May indicate an application not releasing connections cleanly.

nslookup — Name Server Lookup

nslookup queries DNS servers to resolve hostnames to IP addresses (and vice versa) and diagnose DNS configuration issues. It directly queries a DNS server, bypassing the local DNS cache, making it ideal for diagnosing DNS resolution failures and verifying that DNS records are correct.

Syntax nslookup
nslookup [hostname] [DNS_server]
C:\> nslookup google.com — resolve hostname using the system's configured DNS server
C:\> nslookup google.com 8.8.8.8 — query a specific DNS server (Google's public DNS)
C:\> nslookup 8.8.8.8 — reverse DNS lookup: find hostname for an IP address
C:\> nslookup — enters interactive mode (type hostnames at the > prompt; "exit" to quit)
Diagnostic Interpretation
Server: / Address:The first two lines show which DNS server nslookup is querying. If this shows 127.0.0.1 or an unexpected server, DNS is misconfigured.
Non-authoritative answerNormal response — means the DNS server returned a cached answer, not a direct answer from the authoritative nameserver for the domain. Expected in most queries.
Can't find / NXDOMAINThe hostname does not exist in DNS. Either the name is wrong, the DNS record doesn't exist, or you're querying the wrong DNS server.
Query a different serverIf nslookup hostname fails but nslookup hostname 8.8.8.8 succeeds, the problem is the machine's configured DNS server — not DNS in general.

net use — Map Network Drives

net use connects (maps) or disconnects network drives and printers from the command line. It is part of the broader net command family and provides scripted, persistent network share connections — useful for login scripts and automated deployment.

Syntax net use
net use [drive:] [\\server\share] [password] [/user:domain\username] [/persistent:yes|no]
C:\> net use — list all current network drive mappings and their status
C:\> net use Z: \\fileserver\shared — map Z: to a network share
C:\> net use Z: \\server\docs /persistent:yes — reconnect automatically at each login
C:\> net use Z: \\server\docs /user:DOMAIN\jdoe P@ssword1 — map with alternate credentials
C:\> net use Z: /delete — disconnect (unmap) drive Z:
C:\> net use * /delete — disconnect ALL mapped network drives
Key Options
/persistent:yesReconnects the drive mapping at every login. Without this, the mapping is only for the current session.
/user:domain\userConnect with specific credentials. Useful when the share requires a different account than the logged-in user.
UNC pathNetwork shares are referenced via Universal Naming Convention (UNC): \\servername\sharename. The server can be a hostname or IP address.
* (wildcard letter)Use * instead of a drive letter to let Windows assign the next available drive letter automatically.

tracert — Trace Route

tracert traces the network path (the sequence of routers) that packets travel from the local machine to a destination. It reveals each hop along the route, the IP address of each hop, and the round-trip time to each hop. It is the standard tool for identifying where in the network a connectivity failure or performance degradation occurs.

Syntax tracert
tracert [switches] target_name_or_IP
C:\> tracert google.com — trace route to google.com, resolving each hop's hostname
C:\> tracert -d 8.8.8.8 — trace without DNS resolution (faster output)
C:\> tracert -h 15 google.com — limit to 15 hops maximum (default is 30)
Reading Output & Diagnostic Interpretation
Hop numberEach row is one router in the path. Hop 1 is usually your default gateway (router). The final hop is the destination.
Three RTT valuesEach hop shows three round-trip time measurements in milliseconds. Minor variation is normal. Large variation (jitter) or consistently high values indicate latency at that point.
* * *Three asterisks mean no response was received for that hop. Could mean the router blocks ICMP (common and not a problem), or it could indicate the hop is down. If asterisks appear from a certain hop onward, that hop is likely the failure point.
-d switchSkips reverse DNS lookups, making output appear faster. Useful when you only need IP addresses and don't need hostnames resolved.
Stops at a hopIf tracert stops responding at a specific hop and all subsequent hops are asterisks, the failure is at or beyond that hop — useful for escalating to an ISP or upstream network team.

pathping — Path Ping

pathping combines the route-tracing capability of tracert with the packet-loss statistics of ping. It first maps the route (like tracert), then sends 100 packets to each hop and calculates per-hop packet loss percentages and latency statistics. The result is a far more detailed view of network quality than either tool alone.

Syntax pathping
pathping [switches] target_name_or_IP
C:\> pathping 8.8.8.8 — full analysis to 8.8.8.8 (takes ~1–2 minutes)
C:\> pathping -n google.com — skip hostname resolution for faster output
Key Concepts
Phase 1: Route traceDiscovers the path like tracert. Lists each hop with IP and hostname.
Phase 2: StatisticsSends 100 packets to each hop. Reports This Node/Link Lost/Sent — the packet loss percentage at each individual hop. Pinpoints the specific router causing packet loss.
tracert vs. pathpingtracert is fast (seconds) and good for identifying where a route fails. pathping is slow (minutes) but quantifies packet loss at each hop — better for diagnosing intermittent or quality-related issues rather than hard failures.

Exam Focus — tracert vs. pathping

Both trace the route to a destination. The key distinction: tracert shows the path and latency quickly; pathping adds packet loss statistics per hop and takes longer to run. If a scenario asks which tool identifies packet loss at a specific router, the answer is pathping. If the scenario just needs to find where connectivity breaks, either works but tracert is faster.

SECTION 3Disk Management Commands

Disk Management Commands

Disk management commands perform operations on physical drives and their file systems: checking for errors, formatting volumes, and managing partitions from the command line. These commands are especially important in recovery scenarios where the graphical Disk Management tool is unavailable — for example, when working from the Windows Recovery Environment (WinRE).

chkdsk — Check Disk

chkdsk scans a disk volume for file system errors and bad sectors. On NTFS volumes, it verifies the integrity of the file system metadata and can repair many types of corruption. It is the first tool to run when a drive is misbehaving — taking unusually long to open files, showing corruption errors, or after an unexpected shutdown.

Syntax chkdsk
chkdsk [volume] [switches]
C:\> chkdsk — check current drive, read-only (no repairs, just report)
C:\> chkdsk D: — check the D: drive, read-only report
C:\> chkdsk C: /f — fix file system errors on C: (schedules for next reboot if volume is in use)
C:\> chkdsk C: /r — locate bad sectors and recover readable data (implies /f, very slow)
C:\> chkdsk D: /f /r /x — fix errors, scan bad sectors, and force dismount first
Key Switches
/fFix errors. Without /f, chkdsk only reports problems without repairing them. If the volume (e.g., C:) is in use, Windows schedules the check to run before Windows loads on the next reboot.
/rRecover — locates bad sectors and attempts to recover readable data. Implies /f. Performs a physical scan of the drive surface — can take hours on large HDDs. Essential when a drive reports physical errors.
/xForces the volume to dismount before checking, closing any open file handles. Required for non-system volumes that are actively in use. Do not use on the system drive (use /f scheduling instead).
Requires elevationchkdsk /f requires administrator privileges. Running without elevation performs a read-only check only.

format — Format Volume

format prepares a disk volume by writing a new file system structure, effectively erasing all data on the volume. It is used to prepare a new partition for use, change the file system type of a volume, or securely wipe a volume before reuse.

Syntax format
format volume [/fs:filesystem] [/q] [/v:label]
C:\> format D: /fs:ntfs — full format of D: with NTFS file system
C:\> format E: /fs:fat32 /q — quick format of E: with FAT32
C:\> format F: /fs:exfat /v:BackupDrive — exFAT with volume label "BackupDrive"
Key Switches & File System Choices
/fs:ntfsNTFS — New Technology File System. Standard for internal Windows drives. Supports permissions, encryption (EFS), compression, large files, and journaling.
/fs:fat32FAT32 — maximum file size 4 GB, maximum volume size 32 GB via Windows format (larger via third-party tools). Compatible with virtually all OSes and devices. Used for boot USB drives and older compatibility requirements.
/fs:exfatexFAT — Extended FAT. Removes FAT32's 4 GB file size limit. Designed for flash storage (USB drives, SD cards). Cross-platform compatible (Windows, macOS, Linux).
/qQuick format — writes a new file system structure without scanning for bad sectors. Fast but does not detect physical disk problems. Avoid /q if the drive health is uncertain.
/v:labelSets the volume label — the name that appears for the drive in File Explorer. Up to 11 characters for FAT32, 32 for NTFS.

format is Destructive — No Undo

The format command destroys all data on the target volume. There is no confirmation prompt beyond the initial "Proceed with Format (Y/N)?" question. A quick format is not a secure wipe — data can be recovered with forensic tools. For secure disposal, use multiple-pass overwrites or physical destruction.

diskpart — Disk Partition Utility

diskpart is a powerful command-line disk management utility that performs all the operations available in the Disk Management GUI — and more. It is especially valuable in the Windows Recovery Environment (WinRE) or when building custom deployment scenarios, where the Disk Management GUI is unavailable. diskpart operates interactively through a sub-prompt after launch.

Syntax & Interactive Session diskpart
diskpart    (launches interactive prompt — all commands entered at DISKPART> prompt)
C:\> diskpart — launch diskpart, enters interactive mode
DISKPART> list disk — show all physical disks (Disk 0, Disk 1, etc.)
DISKPART> select disk 0 — select Disk 0 as the target for subsequent commands
DISKPART> list partition — show all partitions on the selected disk
DISKPART> select partition 1 — select partition 1
DISKPART> list volume — show all volumes with drive letters, file systems, and sizes
DISKPART> clean — DESTRUCTIVE: removes all partitions and data from selected disk
DISKPART> convert gpt — convert selected disk from MBR to GPT (disk must have no partitions)
DISKPART> create partition primary size=51200 — create 50 GB primary partition
DISKPART> assign letter=D — assign drive letter D to selected volume
DISKPART> exit — leave diskpart and return to normal command prompt
Key Workflow: Select Before Acting
Select modeldiskpart uses a focus model: you must select an object before acting on it. select disk 0 → then partition commands operate on Disk 0. select partition 1 → then commands act on Partition 1.
cleanRemoves all partition and volume information from the selected disk. All data is lost. Used to prepare a disk for a fresh installation. This is the standard first step when converting a drive from MBR to GPT.
convert gptConverts the selected disk's partition scheme from MBR to GPT. Requires the disk to be empty (run clean first). Required for Windows 11 system disks.
activeMarks the selected partition as active — designates it as the bootable partition on an MBR disk. Used when rebuilding boot partitions.

Exam Focus — diskpart clean

The clean command in diskpart is the most dangerous and most tested. It wipes all partitions from the selected disk with no undo. A common exam scenario: "A technician needs to convert a disk from MBR to GPT. What command is used to remove all existing partitions?" The answer is clean (run inside diskpart after selecting the disk). After cleaning, convert gpt changes the partition table type.

SECTION 4File Management Commands

File Management Commands

File management commands create and remove directory structures, and copy files with precision. These are fundamental to scripted deployments, system maintenance, and recovery operations where the graphical interface is not available.

md — Make Directory

md (or mkdir) creates one or more new directories (folders). It can create nested directory structures in a single command, which is useful for scripted setup of complex folder hierarchies.

Syntax md / mkdir
md path     mkdir path    (identical commands)
C:\> md Projects — create folder "Projects" in current directory
C:\> md C:\Data\Reports\2024 — create nested path; all intermediate folders created automatically
C:\> md "My New Folder" — folder name with spaces requires double quotes
Key Behaviors
Recursive creationUnlike some Unix equivalents, Windows' md automatically creates all intermediate directories in a path — no separate switch required.
Already existsIf the directory already exists, md returns "A subdirectory or file already exists." This is not a fatal error — the existing directory is unaffected.

rmdir — Remove Directory

rmdir (or rd) removes an empty directory, or with the right switches, removes a directory tree entirely. By default it only removes empty directories — a safety behavior that prevents accidental data loss.

Syntax rmdir / rd
rmdir [/s] [/q] path
C:\> rmdir OldFolder — remove empty directory (fails if not empty)
C:\> rmdir /s C:\Temp\OldProject — remove directory and all contents (prompts for confirmation)
C:\> rmdir /s /q C:\Temp\OldProject — remove silently without prompting (quiet mode)
Key Switches
/sSubdirectories — removes the directory tree including all files and subfolders. Without this, rmdir fails if the directory has any contents.
/qQuiet — suppresses the "Are you sure (Y/N)?" confirmation prompt. Always pair with /s carefully — rmdir /s /q deletes everything without asking.

robocopy — Robust File Copy

robocopy (Robust File Copy) is a powerful, enterprise-grade file copy utility that handles complex copy tasks that copy and xcopy cannot manage reliably: large file trees with thousands of files, network shares with intermittent connectivity, mirror synchronization, and preservation of all NTFS file attributes and permissions.

Syntax robocopy
robocopy source destination [file(s)] [options]
C:\> robocopy C:\Source D:\Backup — copy top-level files from Source to Backup
C:\> robocopy C:\Source D:\Backup /e — copy all subdirectories including empty ones
C:\> robocopy C:\Source D:\Mirror /mir — mirror: exact copy, deletes files in dest not in source
C:\> robocopy C:\Users \\server\backup\users /e /copyall /r:3 /w:5 — enterprise backup to network share
C:\> robocopy C:\Source D:\Dest /log:C:\robocopy.log — save detailed log file
Key Switches
/eCopy all subdirectories, including empty ones. Without /e, robocopy only copies the top-level directory contents. This is the standard switch for recursive copies.
/mirMirror — makes the destination an exact copy of the source. Files present in the destination but not the source are deleted. Powerful for keeping backups in sync but destructive if used carelessly.
/copyallCopies all file information: data, attributes, timestamps, NTFS security (permissions/ACLs), owner, and auditing information. Essential for migrating user profiles while preserving permissions.
/r:nRetries — number of times to retry a failed copy (default: 1,000,000). Set /r:3 to retry only 3 times before moving on. Critical for network copies that may hit transient errors.
/w:nWait — seconds to wait between retries (default: 30). Set /w:5 for a 5-second wait. Used with /r to control retry behavior on unreliable network connections.
/log:fileWrite the output log to a file rather than the console. Append with /log+: to add to an existing log. Essential for unattended backup operations where results need to be reviewed afterward.

robocopy vs. xcopy

xcopy is an older file copy command that still exists in Windows but lacks robocopy's reliability features (no automatic retry, limited network support, no resumable copies). For any serious file migration or backup task, robocopy is the correct choice. xcopy is effectively deprecated for technical use — use robocopy.

SECTION 5Informational Commands

Informational Commands

Informational commands return data about the system's identity, user accounts, OS version, and provide access to built-in command help. These are quick-fire commands — each takes seconds to run and returns a specific piece of information that a technician frequently needs.

hostname

hostname returns the computer's network name — the name by which it is identified on the local network and in Active Directory. It takes no switches and produces a single line of output.

Syntax hostname
C:\> hostname
DESKTOP-MH7X3K2
Use Cases
Remote supportAsk a user to run hostname when you need the computer name for remote connection or ticket documentation without having to navigate through System Properties.
ScriptingUsed in scripts to dynamically determine the current machine's name for logging or conditional logic. Can also be retrieved via environment variable %COMPUTERNAME%.

net user — User Account Information

net user is part of the net command family and provides information about and management of local user accounts from the command line. It can list accounts, display account details, create, modify, and delete local user accounts.

Syntax net user
net user [username] [password] [options]
C:\> net user — list all local user accounts on this computer
C:\> net user Mike — detailed info for user "Mike": groups, last logon, lockout status, password info
C:\> net user newuser P@ssw0rd! /add — create new local user account
C:\> net user Mike NewP@ss! — reset/change Mike's password
C:\> net user Mike /active:no — disable Mike's account
C:\> net user olduser /delete — permanently delete a local user account
Key Options & Information Returned
net user usernameThe detail view shows: full name, account active status, last logon date/time, password last set, password expiration, logon hours allowed, local group memberships, and account lockout status. Extremely useful for diagnosing login problems.
/addCreates a new local user account. Password may be * to prompt interactively (avoids password in command history).
/active:no / yesEnables or disables the account without deleting it. The secure way to handle departing users at the command line.
Requires elevationCreating, modifying, and deleting accounts requires administrator rights. Viewing account details for your own account may work without elevation.

winver — Windows Version

winver displays a GUI dialog box showing the Windows version, edition, build number, and licensee information. It is the quickest single command for confirming exactly which version and build of Windows is installed.

Syntax winver
C:\> winver — opens the "About Windows" dialog box
Shows: Windows 10 Pro · Version 22H2 · OS Build 19045.3803
Information Displayed
Windows version + editionConfirms "Windows 10 Home," "Windows 11 Pro," etc. — useful for support documentation.
Version numberThe feature update version (e.g., 22H2, 23H2). Indicates which feature release the machine is on — relevant for compatibility and support lifecycle questions.
OS Build numberThe exact build (e.g., 19045.3803). Useful for confirming a specific patch level or comparing against known-issue build numbers.

whoami — Who Am I

whoami displays the username of the currently logged-in user, in the format domain\username or computername\username. It confirms identity in a multi-user or remote environment and, with switches, reveals group memberships and security privileges for the current session.

Syntax whoami
whoami [switches]
C:\> whoami
desktop-mh7x3k2\mike
C:\> whoami /groups — list all security groups the current user belongs to
C:\> whoami /priv — list all privileges assigned to the current user token
C:\> whoami /all — full dump: username, groups, privileges, and logon ID
Use Cases
/groupsConfirms which security groups the current user token includes — including elevation state. An elevated prompt shows the Administrators group as present with "Enabled" attribute; a non-elevated prompt shows it as "Group used for deny only."
Domain vs. localOutput format: DOMAIN\username = domain account. COMPUTERNAME\username = local account. Useful for confirming whether a user is logged in with a domain or local account.

[command name] /? — Built-In Help

Every command-line tool in Windows supports the /? switch, which displays the command's full syntax, all available switches, and brief examples. This is the built-in documentation system for the command line and is explicitly included in Objective 1.5 as a testable item.

Syntax [command] /?
C:\> ipconfig /? — display help for ipconfig
C:\> chkdsk /? — display all chkdsk switches with descriptions
C:\> robocopy /? — robocopy has one of the most comprehensive /? outputs of any command
C:\> help dir — alternative: "help [command]" works for many built-in commands
Exam Relevance
First resortThe /? switch is the correct first step when you know the command name but cannot remember a specific switch. It is faster than searching online and does not require internet access.
Pipe through moreLong help output can be piped: robocopy /? | more pauses after each screenful so you can read all the output without it scrolling by.

SECTION 6OS Management Commands

OS Management Commands

OS management commands interact with the core configuration of Windows: enforcing Group Policy, reporting policy application results, and verifying the integrity of protected system files. These are particularly relevant to enterprise environments and system repair scenarios.

gpupdate — Group Policy Update

gpupdate forces an immediate refresh of Group Policy settings from the Domain Controller (in a domain environment) or applies local Group Policy (in standalone scenarios). By default, Group Policy refreshes automatically every 90 minutes (with a random offset) in background — gpupdate is used when a policy change needs to take effect immediately without waiting for the background cycle.

Syntax gpupdate
gpupdate [/force] [/target:{computer|user}]
C:\> gpupdate — refresh only changed policies (incremental update)
C:\> gpupdate /force — reapply ALL policies, even those that haven't changed
C:\> gpupdate /target:computer — refresh only computer-side policies
C:\> gpupdate /target:user — refresh only user-side policies
Key Switches
/forceForces reapplication of all Group Policy settings regardless of whether they have changed. Use after making policy changes that should take effect immediately, or when troubleshooting a policy that appears not to have been applied.
Reboot promptSome policy changes (like software installation or folder redirection) can only take effect at logon or reboot. gpupdate will prompt: "Do you want to restart?" if such policies are pending.
Standalone vs. domainOn a standalone (non-domain) machine, gpupdate refreshes local Group Policy settings from gpedit.msc. On a domain machine, it contacts the Domain Controller to download updated domain policy.

gpresult — Group Policy Result

gpresult displays a report of which Group Policy Objects (GPOs) are actually applied to the current computer and/or user — along with what settings each policy is enforcing, what policies were blocked, and why. It is the primary tool for troubleshooting Group Policy application issues.

Syntax gpresult
gpresult [/r] [/h filename.html] [/v]
C:\> gpresult /r — summary: list applied GPOs for computer and current user
C:\> gpresult /h C:\gpreport.html — save full HTML report (open in a browser)
C:\> gpresult /v — verbose: full details of applied settings, not just policy names
C:\> gpresult /r /scope computer — computer configuration section only
Key Switches & Output
/rSummary — the most commonly used option. Lists: OS info, domain/site, last policy application time, slow link detection, and the list of GPOs applied to computer and user (in order of application — Last Write Wins for conflicts).
/h file.htmlGenerates a comprehensive, browser-readable HTML report with full GPO details, filtered/blocked policies, and setting-level detail. The most useful output for complex policy troubleshooting.
Denied GPOs sectionThe /r output includes "The following GPOs were not applied because they were filtered out." This section explains WHY a policy did not apply — security filtering, WMI filtering, or OU structure.
gpupdate then gpresultStandard sequence: run gpupdate /force first to ensure the latest policies are applied, then run gpresult /r to verify what is actually in effect.

sfc — System File Checker

sfc (System File Checker) scans all protected Windows system files and replaces corrupted or missing files with a correct version from a cached copy stored in C:\Windows\System32\dllcache or the Windows component store (WinSxS). It is the standard first-line tool for repairing OS corruption — when system files are missing or damaged by malware, failed updates, or accidental deletion.

Syntax sfc
sfc [/scannow] [/verifyonly] [/scanfile]
C:\> sfc /scannow — scan all protected system files and repair any corruption (most common)
C:\> sfc /verifyonly — scan only, no repairs — report integrity violations without fixing
C:\> sfc /scanfile=C:\Windows\System32\notepad.exe — check and repair a single specific file
Key Details
Requires elevationsfc /scannow must be run from an elevated command prompt (Run as administrator). Without elevation it reports insufficient access and does not scan.
Possible results"Windows Resource Protection did not find any integrity violations" = no corruption found. "Windows Resource Protection found corrupt files and successfully repaired them" = repaired. "Windows Resource Protection found corrupt files but was unable to fix some of them" = see CBS.log for details.
CBS.logThe Component-Based Servicing log at C:\Windows\Logs\CBS\CBS.log contains detailed results of sfc operations. When sfc cannot repair files, the log identifies which files are affected.
DISM before or afterIf sfc reports unrepairable corruption, the component store itself may be damaged. Run DISM /Online /Cleanup-Image /RestoreHealth first to repair the component store, then re-run sfc /scannow. DISM downloads replacement files from Windows Update if needed.

Exam Focus — sfc /scannow

When a scenario describes Windows system files that are corrupt, missing, or were altered by malware — and the solution is to repair the OS without reinstalling — the answer is sfc /scannow run from an elevated command prompt. This is one of the most frequently tested commands in the OS management category. Remember: it requires administrator elevation, and the correct switch is /scannow (not /scan or /check).

High-Probability Exam Scenarios

Scenario 1: User can't access a recently moved website, others can → ipconfig /flushdns.
Scenario 2: IP address shows 169.254.x.x → DHCP unreachable; ipconfig /release then /renew.
Scenario 3: Internet works by IP but not by name → DNS problem → nslookup to diagnose.
Scenario 4: Connectivity fails to a remote host — identify where → tracert.
Scenario 5: Need packet loss data per hop → pathping.
Scenario 6: Suspicious outbound connection — identify the process → netstat -ano, match PID in Task Manager.
Scenario 7: Disk errors / corruption after unexpected shutdown → chkdsk C: /f.
Scenario 8: Need to convert drive from MBR to GPT for Windows 11 → diskpart → select disk → clean → convert gpt.
Scenario 9: Windows system files corrupted by malware → sfc /scannow (elevated).
Scenario 10: Group Policy change not taking effect → gpupdate /force, then verify with gpresult /r.
