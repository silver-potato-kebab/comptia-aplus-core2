Given a Scenario, Use Microsoft Windows
Operating System Features and Tools

Objective 1.4 Domain weight: 28% Verb: Scenario 3 tool categories · 22 tools

OVERVIEWIntroduction

Windows ships with a substantial set of built-in administrative tools that allow a technician to diagnose hardware, monitor performance, manage disks, control startup behavior, inspect event logs, and configure the system — all without installing third-party software. Objective 1.4 tests your knowledge of three categories of these tools: Task Manager, the Microsoft Management Console (MMC) snap-ins, and a set of standalone additional tools.

The exam is scenario-based, meaning you will be given a support situation and asked which tool to use, or asked what a specific tool shows you. The key to mastering this objective is not just knowing that each tool exists — it is knowing the specific problem each tool solves, what information it displays, and how to launch it quickly.

How to Launch Any Tool Instantly

Every tool in this objective can be launched from the Run dialog (Win + R) or from the Search bar by typing its executable name. Memorizing the executable names (e.g., taskmgr, eventvwr.msc, msinfo32) is both an exam skill and a real-world productivity skill. Most tools also appear in the Start menu under Windows Administrative Tools, and many are accessible from right-clicking the Start button (Win + X menu).

SECTION 1Task Manager

Task Manager is the most frequently used diagnostic and management tool available to a Windows technician and end user alike. It provides a real-time, multi-tab window into the running state of the operating system — showing active processes, resource consumption, startup impact, logged-in users, and running services. It is the first tool most technicians reach for when a system is slow, unresponsive, or behaving unexpectedly.

Ctrl + Shift + Esc | Ctrl + Alt + Del → Task Manager | Win+X → Task Manager | taskmgr

Windows 11 Task Manager Redesign

Windows 11 redesigned Task Manager with a left-side icon navigation bar instead of tabs across the top. The same information is present — it is reorganized, not removed. The functional content of each section is identical to Windows 10 for exam purposes.

Processes Tab

The Processes tab is the default view when Task Manager opens. It shows every running process on the system — including applications the user launched, background processes, and Windows system processes — grouped into three categories: Apps, Background processes, and Windows processes.

Task Manager — Processes Tab taskmgr → Processes
Apps
User-launched foreground applications currently open. Double-clicking an app expands it to show child processes it has spawned.
Background processes
Processes running in the background without a visible window. Includes system tray apps, updaters, and service host containers.
Windows processes
Core OS processes required for Windows to function — System, Registry, csrss.exe, winlogon.exe, and others. Terminating these can crash the system.
CPU / Memory / Disk / Net columns
Per-process real-time resource consumption. Sortable by clicking column headers. Clicking CPU descending immediately identifies the highest CPU consumer — key for diagnosing slow systems.
End Task
Right-click → End task forcefully terminates a process. Used when an application is frozen (Not Responding). Unsaved data in that application will be lost.
Open file location
Right-click → Open file location opens File Explorer at the executable's directory. Useful for identifying suspicious or unfamiliar processes.
Search online
Right-click → Search online opens a browser search for the process name. Useful for determining whether an unfamiliar process is legitimate or malicious.

Exam Focus — Processes Tab

When a scenario describes an application that has stopped responding or is consuming excessive CPU/RAM, the answer is Task Manager → Processes tab → End Task. Sort by CPU or Memory to identify the problematic process. This is the most fundamental Task Manager use case.

Performance Tab

The Performance tab displays live, continuously updating graphs of system-wide resource utilization. It gives a historical view (typically the last 60 seconds) of how CPU, memory, disk, and network resources have been used — essential for identifying whether a system is consistently resource-constrained or experiencing intermittent spikes.

Task Manager — Performance Tab taskmgr → Performance
CPU
Aggregate CPU utilization percentage over time. Shows number of logical processors, base speed, current speed (with boost), L1/L2/L3 cache sizes, and whether virtualization is enabled. A CPU consistently above 90% indicates a processing bottleneck.
Memory
RAM utilization graph. Displays total installed RAM, in-use amount, committed memory, cached, paged pool, and non-paged pool. Also shows the number of RAM slots used vs. available and the RAM speed. High memory usage with heavy disk activity suggests the system is paging to disk.
Disk 0, 1…
Read/write throughput per physical disk in real time. If disk activity is consistently near 100%, the disk is the bottleneck — common on systems still using mechanical HDDs as the system drive. Disk model and type (SSD/HDD) are shown.
Network
Send/receive throughput per network adapter. Adapter name and connection speed displayed. Useful for identifying network saturation or unexpectedly high background network traffic.
GPU
GPU utilization and dedicated VRAM usage (Windows 10 build 1709+). Each installed GPU is listed separately. Helpful for diagnosing graphics-intensive application performance.
Open Resource Monitor
A link at the bottom of the Performance tab opens Resource Monitor (resmon.exe) for deeper per-process drill-down. Resource Monitor is covered in Section 3 of this objective.

Startup Tab

The Startup tab (moved here from msconfig in Windows 8 and later) lists every program configured to launch automatically when a user logs in. Each entry shows the program name, publisher, startup status (Enabled/Disabled), and a Startup impact rating (High, Medium, Low, or Not measured) — an estimate of how much the program slows down the login process.

Task Manager — Startup Tab taskmgr → Startup
Enable / Disable
Right-click any entry → Disable prevents the program from launching at login. The program is not uninstalled — it simply no longer starts automatically. Re-enabling restores auto-start. Changes take effect at the next login.
Startup impact
High items significantly delay login. Disabling high-impact startup entries is the primary technique for reducing slow login times. Focus on disabling programs the user does not need immediately at login.
Publisher
Identifies the software vendor. "Unknown" publisher is a yellow flag — it may indicate an unsigned application or potentially unwanted software that added itself to startup.
Open file location
Right-click → Open file location reveals where the startup executable lives. Malware commonly places itself in %AppData%, %Temp%, or %ProgramData% and registers as a startup entry.

Exam Focus — Slow Login / Startup

When a scenario describes a computer that logs in slowly or takes a long time to become usable after login, the answer is Task Manager → Startup tab → disable high-impact startup programs. This is the standard first step for addressing slow login performance without reinstalling Windows.

Services Tab

The Services tab provides a flat list view of all Windows services — background programs that run under the service control manager (SCM), typically with no user interface. It shows the service name, PID (Process ID), description, status (Running/Stopped), and group.

Task Manager — Services Tab taskmgr → Services
Start / Stop / Restart
Right-click a service to start, stop, or restart it directly from Task Manager. Useful for a quick restart of a misbehaving service without rebooting the system.
Go to details
Right-click → Go to details jumps to the Details tab and highlights the process hosting that service. Helpful for identifying which svchost.exe instance is running a specific service.
Open Services
A link at the bottom opens the full Services management console (services.msc) where startup type (Automatic, Manual, Disabled), dependencies, recovery actions, and logon accounts can be configured. Task Manager's Services tab is for quick status checks and restarts only.

Users Tab

The Users tab shows all user accounts currently logged into the system — including active sessions and disconnected sessions (users who are logged in but whose session is locked or disconnected via Remote Desktop). Each user entry can be expanded to show the processes running under their account.

Task Manager — Users Tab taskmgr → Users
Logged-in users
Lists all active and disconnected user sessions. A single machine can have multiple users logged in simultaneously if Fast User Switching is enabled or if Remote Desktop sessions are active.
Resource columns
Per-user CPU, memory, disk, and network totals. Useful for identifying which user's session is consuming resources on a shared or terminal server.
Disconnect / Sign off
Disconnect ends the user's active session but leaves their processes running (the user remains logged in, session is locked). Sign off logs the user out completely, terminating all their processes. Requires administrator rights to act on other users' sessions.
Send message
On domain environments or Remote Desktop Session Host servers, an administrator can send a pop-up message to another logged-in user's session.

SECTION 2Microsoft Management Console (MMC) Snap-ins

The Microsoft Management Console (MMC) is a framework — a container application — that hosts modular administrative tools called snap-ins. Each snap-in is a self-contained tool with a specific administrative function: managing disks, viewing event logs, managing users, and so on. You can open snap-ins individually using their own executable name (e.g., eventvwr.msc), or load multiple snap-ins together inside a single custom MMC console (mmc.exe).

Opening MMC Snap-ins

Every snap-in has its own .msc file that can be run directly from the Run dialog (Win + R), the Search bar, or a Command Prompt. You can also open a blank MMC console by running mmc, then use File → Add/Remove Snap-in to build a custom console with exactly the tools you need — a common technique for system administrators who manage multiple aspects of a server simultaneously.

The quick-reference table below summarizes all eight snap-ins tested in Objective 1.4 before each is covered in depth.

Event Viewer (eventvwr.msc)

Event Viewer is the central repository for Windows log data. Every significant OS event — successful logins, failed logins, service crashes, driver errors, application errors, warnings — is recorded in an event log. Event Viewer is the first tool to consult when diagnosing a system that crashes, throws errors, or behaves unexpectedly without obvious cause.

Win + R → eventvwr.msc | Win+X → Event Viewer | Control Panel → Administrative Tools
Event Viewer eventvwr.msc
Windows Logs → Application
Events generated by applications and programs. Application crashes, database errors, and software-specific warnings appear here. The faulting module and exception code in a crash event often pinpoint the cause.
Windows Logs → System
Events generated by the Windows operating system and its components — driver failures, service start/stop events, hardware errors, disk errors, and kernel events. The most important log for hardware troubleshooting.
Windows Logs → Security
Audit events: successful and failed login attempts, privilege use, account management changes, and object access (if auditing is enabled). Critical for security investigations. Requires admin rights to view.
Windows Logs → Setup
Events related to application installation and Windows component installation. Useful for diagnosing failed software deployments.
Windows Logs → Forwarded Events
Events collected from remote computers (when Windows Event Forwarding is configured). Empty on standalone machines.
Applications and Services Logs
Application-specific logs for Windows components (PowerShell, Task Scheduler, WMI, etc.) and third-party applications. More granular than the main Windows Logs.
Event levels
Critical — system failure requiring immediate attention. Error — significant problem, functionality affected. Warning — potential problem, not yet critical. Information — normal operational event. Verbose — detailed diagnostic data.
Event ID
A numeric code identifying the specific event type. Event IDs are consistent across Windows versions — e.g., Event ID 41 = unexpected shutdown (power loss), 6008 = unexpected shutdown recorded after restart, 4625 = failed login attempt. Searching an Event ID online yields Microsoft documentation and community diagnoses.
Filter Current Log
Right-click a log → Filter Current Log to narrow events by level, date/time range, Event ID, or source. Essential for finding relevant events in logs with thousands of entries.
Custom Views
Pre-built filtered views — including Administrative Events, which aggregates Critical, Error, and Warning events from all logs into a single view. Saves time when performing a general health check.

Exam Focus — Event Viewer

When a scenario says "a computer keeps crashing" or "a service keeps stopping" or "a user is receiving login errors" — Event Viewer is the diagnostic tool. Know that the System log covers OS and hardware events, the Application log covers software events, and the Security log covers login and audit events. Event IDs 41 and 6008 specifically relate to unexpected shutdowns — common exam questions.

Disk Management (diskmgmt.msc)

Disk Management is the primary GUI tool for working with physical disks and their partitions and volumes in Windows. It provides a graphical disk map showing every physical disk, its partitions, filesystem, health status, and drive letter assignments.

Win + R → diskmgmt.msc | Win+X → Disk Management | Computer Management → Storage → Disk Management
Disk Management diskmgmt.msc
Initialize Disk
A new uninitialized disk (fresh from the factory or wiped) must be initialized before partitions can be created. Disk Management prompts to initialize with MBR (legacy, max 2.2 TB, max 4 primary partitions) or GPT (modern, large drives, up to 128 partitions). GPT is the correct choice for new disks on modern systems.
Create / Delete volumes
Right-click unallocated space → New Simple Volume to create a new partition. Right-click an existing partition → Delete Volume to remove it (data is destroyed). Right-click → Format to reformat an existing partition with a new filesystem (NTFS, FAT32, exFAT).
Extend / Shrink Volume
Extend Volume adds unallocated space adjacent to (or on the same disk as) a volume, making it larger. Shrink Volume reduces a volume's size to free up unallocated space that can be used for a new partition. Shrink cannot move files — the amount shrinkable may be limited by immovable files (like the pagefile) near the end of the volume.
Change Drive Letter
Right-click any volume → Change Drive Letter and Paths to assign, change, or remove a drive letter. Useful when a drive letter conflicts with another device or a letter is needed for application compatibility. Note: changing the system drive letter will break Windows.
Disk status indicators
Online = healthy and accessible. Offline = disk is present but not accessible (right-click → Online to bring it back). Foreign = dynamic disk from another computer (import it). Failed = disk has an error and data may be at risk.
Volume types
Simple = standard single-disk partition. Spanned = single volume spread across multiple disks (no redundancy). Striped (RAID 0) = data striped across disks for speed (no redundancy). Mirrored (RAID 1) = duplicate data across two disks. RAID-5 = striped with parity. Dynamic disks required for spanned/striped/mirrored volumes.

Task Scheduler (taskschd.msc)

Task Scheduler allows Windows and applications to run programs, scripts, or commands automatically at specified times or in response to specific system events — without any user interaction. It is the backbone of automated maintenance in Windows, and many Windows features (Automatic Updates check-ins, disk defragmentation, antivirus definition updates) rely on scheduled tasks behind the scenes.

Win + R → taskschd.msc | Search → Task Scheduler | Computer Management → System Tools → Task Scheduler
Task Scheduler taskschd.msc
Task Library
The left-pane tree view organized in folders. Task Scheduler Library is the root. Microsoft's own tasks live under Microsoft\Windows\. Third-party applications create folders under the root. Browse here to see all tasks on the system, including malicious persistence mechanisms that may have registered themselves as scheduled tasks.
Triggers
The conditions that cause a task to run. Triggers include: On a schedule (daily, weekly, monthly, one time), At logon, At startup, On an event (a specific Event ID in a specific log), On idle, On connection/disconnect, and more. A single task can have multiple triggers.
Actions
What the task does when triggered. Actions include: Start a program (run an executable, script, or command), Send an email (deprecated), and Display a message (deprecated). Most tasks use Start a program. The program path and any arguments are specified here.
Conditions
Optional additional conditions that must be true for the task to run even if the trigger fires — for example, only run when the computer is idle, only run when on AC power (not battery), or only run when a specific network connection is available.
Security context
Tasks run under a specified user account. Tasks can be set to Run whether user is logged on or not (runs in the background silently, requires the password) and Run with highest privileges (runs as administrator). Important for administrative tasks that need elevated rights.
Last Run Result
In the middle pane task list, the Last Run Time and Last Run Result columns show when the task last executed and whether it succeeded (0x0 = success) or failed (any non-zero code). Useful for verifying that backup, update, or maintenance tasks are actually running.

Device Manager (devmgmt.msc)

Device Manager is the central control panel for all hardware devices recognized by Windows. It displays every hardware component the OS is aware of, shows the driver status for each device, and allows drivers to be updated, rolled back, disabled, or uninstalled. It is the primary tool for hardware troubleshooting and driver management.

Win + R → devmgmt.msc | Win+X → Device Manager | Right-click This PC → Manage → Device Manager
Device Manager devmgmt.msc
Yellow exclamation (⚠)
A yellow warning triangle on a device indicates a driver problem — the device is present but not functioning correctly. The driver may be missing, corrupt, or incompatible. Right-click → Properties → Details for the error code and description.
Red X (✗)
The device has been disabled — either manually by an administrator, or automatically by Windows due to a resource conflict. Right-click → Enable device to re-enable it.
Down arrow (↓)
The device has been manually disabled by the user or administrator. Distinct from a hardware error — the device is working but turned off in software.
Update driver
Right-click a device → Update driver offers two options: Search automatically (queries Windows Update) or Browse my computer (manual installation from a downloaded driver package). For the most current drivers, always download directly from the manufacturer's website.
Roll back driver
Right-click → Properties → Driver tab → Roll Back Driver reverts to the previously installed driver version. Essential when a driver update breaks functionality — for example, a GPU driver update that causes display issues. Only available if a previous driver version was installed.
Uninstall device
Removes the driver from the system. The option to "delete the driver software for this device" also removes the driver package from Windows' driver store. On the next reboot (or Scan for hardware changes), Windows will attempt to reinstall the driver. Used to force a clean driver reinstall.
Scan for hardware changes
Action menu → Scan for hardware changes forces Windows to re-detect all connected hardware. Used after physically installing a new device or after uninstalling a driver to prompt Windows to reinstall it immediately.
View → Show hidden devices
Reveals devices that are not currently connected (ghosted devices) and non-plug-and-play drivers. Useful for finding leftover driver entries from previously connected hardware.

Exam Focus — Device Manager Icons

The yellow exclamation mark is the most tested Device Manager symbol. It means the device has a driver problem — not that the device is absent. The fix is to update or reinstall the driver, not to replace the hardware. A red X means disabled, not broken. Know the distinction.

Certificate Manager (certmgr.msc)

Certificate Manager displays and manages digital certificates stored for the currently logged-in user account. Digital certificates are cryptographic credentials issued by a Certificate Authority (CA) that establish identity and enable encryption for secure communications (HTTPS, email signing, code signing, smart card authentication, etc.).

Win + R → certmgr.msc
Certificate Manager certmgr.msc
Personal
Certificates issued to this user — used for email encryption (S/MIME), client authentication, smart card login, and other user-specific cryptographic operations.
Trusted Root CAs
The list of Certificate Authorities that Windows implicitly trusts. Any certificate signed by a CA in this list is trusted. Rogue or unauthorized root certificates installed here are a serious security threat — malware sometimes installs fake root CAs to enable HTTPS interception.
Intermediate CAs
Certificates of intermediate Certificate Authorities that form the chain of trust between an end-entity certificate and a Trusted Root CA. Certificate errors often occur when an intermediate CA certificate is missing from this store.
User vs. Computer store
certmgr.msc manages the current user's certificate store. To manage the computer-level certificate store (trusted for all users and services on the machine), use the Certificates snap-in within a custom MMC console targeting the Local Computer account — requires administrator rights.

Local Users and Groups (lusrmgr.msc)

Local Users and Groups is the management interface for user accounts and security groups stored in the local Security Account Manager (SAM) database — the accounts that exist on this machine independently of any domain. It provides more granular control than the basic account settings in the Settings app.

Win + R → lusrmgr.msc | Computer Management → System Tools → Local Users and Groups

Pro/Enterprise Only

lusrmgr.msc is available only on Windows Pro, Pro for Workstations, and Enterprise editions. On Windows Home, attempting to run it produces an error. Home users must manage accounts through Settings → Accounts instead, which offers limited options by comparison.

Local Users and Groups lusrmgr.msc
Users folder
Lists all local user accounts including built-in accounts (Administrator, Guest, DefaultAccount, WDAGUtilityAccount). Double-clicking a user opens their properties: full name, description, password options (cannot change, never expires, account is disabled), and group memberships.
Groups folder
Lists local security groups. The critical built-in groups are: Administrators (full system control), Users (standard limited access), Guests (minimal temporary access), Remote Desktop Users (RDP login permission), and Power Users (legacy elevated group — equivalent to standard user in modern Windows).
Creating users
Right-click Users folder → New User. Set username, full name, description, and password. Options to force password change at next login, prevent user from changing password, or set the password to never expire. New users are not added to any group by default — they must be manually added to the Users group (or another group) to have usable permissions.
Managing group membership
Double-click a user → Member Of tab to add or remove group memberships. Or double-click a group → Add button to add users to that group. Adding a user to the Administrators group elevates them to full admin rights — a significant security decision.
Disabling accounts
Double-click a user → check "Account is disabled" to disable the account without deleting it. Disabled accounts cannot log in. This is the correct way to handle departing employees — disable rather than delete, in case their profile or files need to be accessed. Disabled accounts appear with a down-arrow icon in the Users list.

Performance Monitor (perfmon.msc)

Performance Monitor is a professional-grade performance data collection and analysis tool that goes well beyond the real-time snapshot in Task Manager. It allows a technician to track dozens of system performance counters over extended periods, save the data for later analysis, compare baselines to current values, and diagnose intermittent performance problems that may not be reproducible on demand.

Win + R → perfmon.msc | Win + R → perfmon | Search → Performance Monitor
Performance Monitor perfmon.msc
Performance counters
Measurable values from hundreds of categories — Processor, Memory, LogicalDisk, PhysicalDisk, Network Interface, Process, and many more. Each counter tracks a specific metric, e.g., Processor → % Processor Time, Memory → Available MBytes, PhysicalDisk → Avg. Disk Queue Length.
Real-time monitoring
The default Performance Monitor view shows selected counters as live-updating line graphs. Add counters using the green + button. Multiple counters from different categories can be overlaid on the same chart for correlation analysis.
Data Collector Sets
A named collection of counters that can be scheduled to run automatically and save data to log files. Used for capturing performance data over hours or days without human monitoring — essential for diagnosing intermittent slowdowns that occur overnight or after hours.
System Diagnostics Report
Under Reports → System → System Diagnostics: a built-in Data Collector Set that runs for 60 seconds and generates a comprehensive HTML report of system performance, hardware, software configuration, and potential issues. A quick automated health assessment.
Key diagnostic counters
Memory → Pages/sec >20 sustained = heavy paging (insufficient RAM). PhysicalDisk → Avg. Disk Queue Length >2 = disk bottleneck. Processor → % Processor Time sustained near 100% = CPU bottleneck. Network Interface → Bytes Total/sec near adapter capacity = network saturation.

Performance Monitor vs. Task Manager

Task Manager is for real-time, immediate diagnosis — "what is consuming resources right now?" Performance Monitor is for historical and trend analysis — "what was happening to this system at 2 AM when users report it was slow?" Use Task Manager first; escalate to Performance Monitor when the problem is not immediately visible or reproducible.

Group Policy Editor (gpedit.msc)

The Local Group Policy Editor is the graphical interface for managing the thousands of Windows settings governed by Group Policy — system-wide and per-user configuration settings that go far beyond what the Settings app exposes. As established in Objective 1.3, this tool is available only on Pro, Pro for Workstations, and Enterprise editions.

Win + R → gpedit.msc | Search → Edit group policy

Pro/Enterprise Only

gpedit.msc is not installed on Windows Home. Running it on Home editions returns a "Windows cannot find 'gpedit.msc'" error. This is an edition limitation, not a permissions issue — the tool simply does not exist on Home.

Local Group Policy Editor gpedit.msc
Computer Configuration
Settings applied to the computer regardless of which user is logged in. Takes effect at system startup. Controls Windows settings, security settings (password policies, account lockout, audit policy), and software restrictions that apply system-wide.
User Configuration
Settings applied to user accounts when they log in. Controls desktop appearance, Start menu restrictions, Control Panel access, folder redirection, and per-user software behavior. Settings here apply to whoever is logged in on this machine.
Administrative Templates
The largest category — thousands of registry-backed settings exposed as readable policy items with descriptions of each setting and its effect. Navigate to Computer Configuration → Administrative Templates → Windows Components to find settings for Windows Update, Windows Defender, Remote Desktop, OneDrive, and hundreds more.
Security Settings
Under Computer Configuration → Windows Settings → Security Settings: password policies (length, complexity, expiration), account lockout policy (how many failed attempts before lockout), local policies (user rights assignments, security options like UAC behavior), and Windows Firewall with Advanced Security.
Policy states
Each policy item has three states: Not Configured (policy has no effect — default), Enabled (policy is active), Disabled (policy is explicitly turned off, overriding any default that would enable it). Not Configured and Disabled are different — Disabled explicitly prevents other policy sources from enabling the setting.

SECTION 3Additional Tools

Beyond Task Manager and the MMC snap-ins, Windows includes a set of standalone diagnostic and maintenance tools that are accessed via their own executable. These six tools cover hardware inventory, deep resource analysis, system configuration, disk maintenance, and the Registry.

System Information (msinfo32.exe)

System Information generates a comprehensive, read-only snapshot of the entire hardware and software configuration of the local computer. It is the fastest single-stop tool for gathering hardware specifications, OS version details, driver information, and environmental variables — without opening Device Manager or digging through multiple Settings pages.

Win + R → msinfo32 | Search → System Information | Start → Windows Administrative Tools
System Information msinfo32.exe
System Summary
The default view. Shows OS name and version, OS build number, system manufacturer and model, BIOS version and date, BIOS Mode (UEFI or Legacy), Secure Boot State (On or Off), total physical memory, available physical memory, total virtual memory, and processor information. Extremely useful for quickly confirming hardware specs.
Hardware Resources
IRQs, I/O addresses, DMA channels, and memory addresses assigned to hardware. The Conflicts/Sharing node highlights any hardware resource conflicts — devices sharing an interrupt that may cause instability.
Components
Detailed information on every hardware category: Display (adapter, resolution, driver version, VRAM), Network (adapter name, MAC address, IP, speed), Storage (drives, optical devices), Sound, Ports (COM, LPT), USB, and more. Very useful when a device's specs need to be documented or verified.
Software Environment
System drivers, environment variables, print jobs, network connections, running tasks, loaded modules, services, startup programs, OLE registration, and Windows Error Reporting. A complete software inventory.
Find / Export
The Find field at the bottom searches across all categories — useful for quickly locating a specific piece of information. File → Export saves the entire report as a plain-text .NFO file for documentation or remote support.

Exam Focus — msinfo32 Key Data Points

On the exam, msinfo32 is the answer when a scenario asks how to determine: the BIOS mode (UEFI vs Legacy), Secure Boot status, total installed RAM, processor model, or OS build number — all from a single tool. It is read-only and cannot be used to change any settings.

Resource Monitor (resmon.exe)

Resource Monitor is a real-time diagnostic tool that provides per-process detail on CPU, memory, disk, and network usage at a level of granularity that exceeds Task Manager. Where Task Manager shows aggregate resource consumption, Resource Monitor shows exactly which files a process is reading, which network connections it has open, and what handles it holds.

Win + R → resmon | Task Manager → Performance tab → Open Resource Monitor | Search → Resource Monitor
Resource Monitor resmon.exe
Overview tab
A four-panel summary showing CPU, Disk, Network, and Memory utilization simultaneously with sparkline graphs for each. The left column shows per-process breakdown for each resource. Checking a process in the CPU pane filters all other panes to show only that process's activity.
CPU tab
Per-process CPU usage, thread counts, CPU cycles, and context switches. The Associated Handles and Associated Modules panels below show file handles and DLLs loaded by the selected process — useful for identifying what resources a process is using or locking.
Memory tab
Per-process Working Set (RAM actively used), Commit (virtual memory reserved), Shareable, and Private memory. The bottom panel shows the physical memory usage map — blue (in use), green (modified), yellow (standby), grey (free). Extremely helpful for RAM troubleshooting and diagnosing memory leaks.
Disk tab
Per-process disk read/write activity showing the actual file paths being read or written. This answers questions like "why is my disk thrashing?" — you can see exactly which process is reading/writing which files in real time. Also shows disk queue length over time.
Network tab
Per-process network connections showing source/destination IP addresses, ports, and protocol. The TCP Connections panel shows every open TCP connection with its state (ESTABLISHED, TIME_WAIT, LISTENING, etc.). Useful for identifying unexpected outbound connections from suspicious processes.

System Configuration (msconfig.exe)

System Configuration (commonly referred to by its executable name, msconfig) is a utility for managing how Windows boots and what loads at startup. It is particularly valuable for troubleshooting via selective startup — a method of isolating startup problems by progressively disabling components to identify which one is causing an issue.

Win + R → msconfig | Search → System Configuration
System Configuration msconfig.exe
General tab
Three startup options: Normal startup (loads all drivers and services — standard operation), Diagnostic startup (loads only basic devices and services — similar to Safe Mode but a full-OS boot), and Selective startup (allows choosing whether to load system services, startup items, or the original boot configuration). Diagnostic startup is a quick way to test whether a problem is caused by third-party services.
Boot tab
For systems with multiple OS installations, the Boot tab selects the default OS and timeout. Advanced options include setting the number of processor cores and maximum memory for boot (used to test behavior with limited resources). Safe boot checkbox configures the next boot into Safe Mode — useful for cases where the system can't boot into Safe Mode using F8. Boot log saves startup information to C:\Windows\ntbtlog.txt.
Services tab
Lists all registered Windows services with Enable/Disable checkboxes. The critical option: "Hide all Microsoft services" checkbox filters out Windows-built-in services, leaving only third-party services visible. Unchecking all remaining services and rebooting disables all third-party services — a clean-boot technique for isolating software conflicts.
Startup tab
In Windows 8 and later, this tab simply contains a link to Task Manager's Startup tab where startup programs are now managed. In Windows 7 and earlier, startup programs were managed directly here.
Tools tab
A convenient launcher for 20+ Windows administrative tools — including Event Viewer, Performance Monitor, Resource Monitor, UAC settings, System Restore, and the Command Prompt. Each tool shows its command-line path, making it a useful reference.

Exam Focus — Clean Boot with msconfig

The clean boot technique uses msconfig to isolate startup problems. The steps are: (1) Services tab → Hide all Microsoft services → Disable all, (2) Task Manager Startup tab → Disable all, (3) Reboot. If the problem disappears, it is caused by a third-party service or startup program. Re-enable items in batches to identify the culprit. This is a standard exam-tested troubleshooting methodology.

Disk Cleanup (cleanmgr.exe)

Disk Cleanup is a built-in utility that identifies and removes categories of unnecessary files that accumulate on Windows systems over time — temporary files, cached data, old Windows installation files, error reports, and more. It is the standard tool for reclaiming disk space without manually hunting through the file system.

Win + R → cleanmgr | Search → Disk Cleanup | File Explorer → right-click drive → Properties → Disk Cleanup button
Disk Cleanup cleanmgr.exe
Standard categories
Downloaded Program Files (ActiveX controls, Java applets), Temporary Internet Files (browser cache), Windows Error Reports, DirectX Shader Cache, Delivery Optimization Files, Recycle Bin contents, Temporary files (files in %TEMP% folders), Thumbnails, and more. Each category shows how much space will be reclaimed.
Clean up system files
A button that re-runs Disk Cleanup with administrator privileges, revealing additional categories: Windows Update Cleanup (old update packages — often the largest category, can be many gigabytes), Previous Windows installation(s) (Windows.old folder from an upgrade), and Device driver packages. This is where the most significant disk space recovery happens.
Windows.old
After an OS upgrade, the previous Windows installation is stored in C:\Windows.old as a rollback option. This folder is automatically cleaned up by Windows after 10 days. If a user needs the space sooner, Disk Cleanup → Clean up system files → Previous Windows installation(s) removes it immediately.
Storage Sense (modern alternative)
In Windows 10/11, Storage Sense (Settings → System → Storage) provides an automated, scheduled version of disk cleanup that can run automatically when disk space runs low. For the exam, cleanmgr remains the expected answer for manual disk cleanup tasks.

Disk Defragment (dfrgui.exe)

Optimize Drives (the modern name for the Disk Defragmenter, accessed via dfrgui.exe) maintains drive performance by reorganizing how data is stored on disk. The tool behaves differently depending on whether the target drive is a traditional Hard Disk Drive (HDD) or a Solid-State Drive (SSD) — an important distinction for both the exam and real-world use.

Win + R → dfrgui | Search → Defragment and Optimize Drives | File Explorer → right-click drive → Properties → Tools tab → Optimize
Optimize Drives (Disk Defragmenter) dfrgui.exe
HDD — Defragmentation
On mechanical HDDs, files become fragmented over time — their data is written in non-contiguous blocks scattered across the platters. The read head must physically seek to each fragment, slowing reads. Defragmentation rewrites fragmented files contiguously, reducing seek time. The Analyze button shows the current fragmentation percentage before running a defrag. A full defrag on a heavily fragmented HDD can take hours.
SSD — TRIM / Retrim
SSDs do not benefit from defragmentation (and excessive writes could reduce their lifespan). Instead, dfrgui runs a Retrim operation on SSDs — sending TRIM commands that notify the SSD controller which data blocks are no longer in use, allowing the SSD to reclaim those blocks for future writes. This maintains long-term SSD write performance. Windows identifies drive type and runs the appropriate operation automatically.
Scheduled optimization
By default, Windows schedules automatic optimization weekly for all drives. The schedule can be customized (daily/weekly/monthly) or disabled. Scheduled defragmentation is enabled by default and generally sufficient — manual defragmentation is rarely necessary on modern systems.
Analyze
Reports the current fragmentation percentage of a selected drive without making any changes. Use this to assess whether defragmentation is necessary before committing to a potentially lengthy operation. Greater than 10% fragmentation on an HDD generally warrants a defrag.

Exam Focus — HDD vs. SSD Optimization

You should not defragment an SSD. The exam may present a scenario asking what to do to maintain SSD performance — the answer is TRIM (which dfrgui handles automatically as "Retrim"). Defragmenting an SSD does not improve performance and unnecessarily wears the drive. Windows is smart enough to run the right operation for each drive type — but the technician should understand why.

Registry Editor (regedit.exe)

The Registry Editor provides direct read/write access to the Windows Registry — the hierarchical database that stores virtually all configuration settings for Windows, its services, hardware drivers, and installed applications. Every user account preference, every installed application's settings, every hardware configuration, and most Windows behavior settings are ultimately stored in the Registry.

Win + R → regedit | Search → Registry Editor | (requires administrator confirmation via UAC)

Use With Extreme Caution

Incorrect Registry edits can render Windows unbootable, prevent applications from running, or cause unpredictable system behavior. Always export (back up) a key before modifying it: right-click the key → Export, save the .reg file. This allows the change to be undone by double-clicking the exported file. Do not modify Registry keys you do not understand.

Registry Editor regedit.exe
HKEY_LOCAL_MACHINE (HKLM)
Settings that apply to the entire computer regardless of which user is logged in. Includes hardware configuration (HKLM\HARDWARE), installed software (HKLM\SOFTWARE), system services (HKLM\SYSTEM), and security settings (HKLM\SECURITY, HKLM\SAM). The most important hive for system-level configuration.
HKEY_CURRENT_USER (HKCU)
Settings for the currently logged-in user — desktop preferences, user-specific application settings, mapped network drives, and user-level software configuration. Changes here affect only the current user's profile. HKCU is a shortcut into HKLM\SOFTWARE\Classes and the current user's profile hive.
HKEY_USERS (HKU)
Contains subkeys for every user profile loaded on the system. HKCU is actually a pointer to the current user's subkey under HKU. Administrators can edit settings for other user profiles by navigating directly to their subkey under HKU.
HKEY_CLASSES_ROOT (HKCR)
File type associations and COM object registrations — which application opens a .pdf file, how context menus are constructed, and what icons appear for file types. A merge of HKLM\SOFTWARE\Classes and HKCU\SOFTWARE\Classes; per-user settings take precedence.
HKEY_CURRENT_CONFIG (HKCC)
A pointer to the current hardware profile under HKLM\SYSTEM\CurrentControlSet\Hardware Profiles\Current. Contains settings for the active hardware configuration. Rarely edited directly.
Value types
REG_SZ — plain text string. REG_DWORD — 32-bit integer (0 or 1 commonly used for on/off flags). REG_QWORD — 64-bit integer. REG_BINARY — raw binary data. REG_MULTI_SZ — multiple strings. REG_EXPAND_SZ — string containing environment variable references (e.g., %SystemRoot%).
Find (Ctrl + F)
Searches across all keys, value names, and value data. Essential for finding where a specific application stores its settings or locating a malware persistence key by name. Use Find Next (F3) to continue searching after the first result.
Export / Import
Right-click a key → Export saves it (and all subkeys) as a .reg file — human-readable text. Double-clicking a .reg file merges its contents back into the Registry. File → Import achieves the same result. This is the standard backup method before making Registry changes.

Exam Focus — Registry Hives

Know the five root hives and what each contains: HKLM = machine-wide settings, HKCU = current user settings, HKU = all user profiles, HKCR = file associations, HKCC = current hardware profile. Common exam questions ask which hive to look in for a specific type of setting — system-wide settings are in HKLM; per-user settings are in HKCU.

Scenario 1: Application is unresponsive → Task Manager → Processes → End Task.
Scenario 2: Computer boots slowly / slow to become usable after login → Task Manager → Startup → disable high-impact programs.
Scenario 3: A device has a yellow exclamation mark → Device Manager → update or reinstall driver.
Scenario 4: A new driver update causes display problems → Device Manager → Roll Back Driver.
Scenario 5: System crashes without explanation → Event Viewer → System log → search for Critical/Error events near the crash time.
Scenario 6: A new hard drive is not visible in File Explorer → Disk Management — the disk needs to be initialized and a volume created.
Scenario 7: Need to know BIOS mode or Secure Boot state → msinfo32 → System Summary.
Scenario 8: Computer is slow — need to determine whether it's CPU, RAM, or disk → Task Manager → Performance tab.
Scenario 9: Low disk space → Disk Cleanup → Clean up system files to remove Windows Update cache.
Scenario 10: Application conflict after Windows starts — clean boot → msconfig → Services → Hide Microsoft → Disable all, then Startup items off.
