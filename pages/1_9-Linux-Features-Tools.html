OVERVIEWIntroduction

Objective 1.9 covers Linux — the third major desktop operating system family alongside Windows (objective 1.7) and macOS (objective 1.8) — with a strong emphasis on the command-line interface, since Linux administration is overwhelmingly terminal-driven compared to the more GUI-centric workflows of Windows and macOS. This objective is dense with specific commands, and the exam expects recognition-level familiarity: given a command, know what it does; given a task, know which command accomplishes it.

Organize this material the way the objective itself does — commands grouped by what they're for (file management, filesystem management, administrative tasks, package management, network diagnostics, system information, text editing) — plus a handful of critical configuration files and core OS components that tie the command-line tools together into a working system.

A Note on Distributions

"Linux" isn't a single operating system but a kernel (Part on OS Components, below) at the core of many different distributions (distros) — Ubuntu, Debian, Fedora, Red Hat Enterprise Linux (RHEL), and many others. Most of the commands in this objective work identically across virtually all distributions, since they're part of the standard core Unix/Linux toolset. The one major exception is package management (Part 4), where the specific command differs depending on which distribution family you're working with.

Common Pitfall — rm Has No Recycle Bin

Unlike deleting a file through a graphical file manager, rm at the command line permanently deletes the target with no Recycle Bin/Trash safety net by default — especially dangerous when combined with -rf (recursive, forced, no confirmation) on the wrong path. This is a frequently cited real-world cautionary tale in Linux administration, and the exam expects you to understand rm -rf as a powerful, unforgiving command that demands careful use.

chmod — Understanding Permission Syntax

chmod permissions are commonly expressed as a three-digit number, where each digit represents permissions for owner, group, and others respectively, calculated by adding together: 4 (read), 2 (write), and 1 (execute).

ValuePermissions Granted
7Read + Write + Execute (4+2+1)
6Read + Write (4+2)
5Read + Execute (4+1)
4Read only
0No permissions

So chmod 755 script.sh grants the owner full read/write/execute (7), while the group and others each get read/execute only (5) — a very common permission set for an executable script meant to be run, but not modified, by other users.

PART 2Filesystem Management

CommandSyntax ExamplePurpose
fsckfsck /dev/sda1"File system consistency check" — scans a filesystem for errors/corruption and attempts repair; conceptually parallel to chkdsk on Windows, typically run on an unmounted filesystem to avoid conflicts with active use
mountmount /dev/sdb1 /mnt/usbAttaches a filesystem (a drive, partition, or network share) to a specific point in the directory tree, making its contents accessible at that location; umount performs the reverse, detaching it

Why "Mounting" Matters on Linux

Unlike Windows, which assigns separate drive letters (C:, D:, E:) to different drives/partitions, Linux integrates all storage into a single unified directory tree starting at the root (/) — a newly connected drive doesn't get its own letter, it gets mounted at a specific folder/path within that existing tree (commonly somewhere under /mnt or /media), after which its contents simply appear as a folder at that location.

PART 3Administrative

CommandSyntax ExamplePurpose
susu - username"Switch user" — starts a new session logged in as a different user (commonly root), requiring that target user's password; without a username specified, defaults to switching to root
sudosudo apt update"Superuser do" — runs a single specified command with elevated (root-level) privileges, requiring the current user's own password (not root's), rather than switching the entire session to another user

Exam Angle — su vs. sudo

This is a frequently tested distinction: su switches the entire active session to a different user account (commonly root) and stays that way until the user exits that session, requiring the target account's password. sudo elevates privileges for just a single command, then immediately returns to the normal user's own session, requiring the current user's own password rather than root's. sudo is generally considered the safer, more auditable practice in modern Linux administration, since it avoids leaving an entire session running with full root privileges longer than necessary.

PART 4Package Management

Unlike Windows or macOS, where software is typically installed via individual downloaded installers, Linux distributions overwhelmingly install and update software through a centralized package manager, which downloads software (and automatically resolves any required dependencies) from a configured repository.

CommandSyntax ExamplePurpose
aptsudo apt install nginxThe package manager used on Debian-based distributions (Debian, Ubuntu, and their many derivatives) — installs, updates, and removes software packages
dnfsudo dnf install nginxThe package manager used on Red Hat-based distributions (Fedora, RHEL, and related distributions) — serves the same fundamental role as apt, but on a different distribution family

Exam Angle

The key takeaway: apt = Debian/Ubuntu family, dnf = Red Hat/Fedora family — the same fundamental task (install/update/remove software) is accomplished with a different command depending on which distribution family you're working with. Don't try to use apt on a Fedora system or dnf on an Ubuntu system; they belong to different distribution ecosystems.

Connecting Back to Core 1 Networking

These commands are the practical, hands-on tools for testing the concepts covered throughout Core 1's networking domain: ping tests basic reachability, dig troubleshoots DNS resolution (objective 2.3), and traceroute reveals the path packets take across routers (objective 2.5). Recognizing each command's purpose is largely a matter of connecting it back to the underlying networking concept it's used to test or diagnose.

CommandSyntax ExamplePurpose

Exam Angle — du vs. df

A commonly tested distinction: du reports how much space a specific file or folder is using (a bottom-up view, asking "how big is this thing?"), while df reports how much total space is used/free across entire mounted filesystems (a top-down view, asking "how full is this drive?"). A scenario asking "which specific folder is consuming all the disk space" points to du; a scenario asking "is this drive nearly full" points to df.

top vs. ps — Real-Time vs. Snapshot

top provides a continuously refreshing, interactive live view — ideal for actively watching resource usage as it happens, such as identifying a runaway process consuming excessive CPU in real time. ps provides a single, static snapshot at the moment the command runs — useful for scripting, piping to other commands (like grep to filter for a specific process), or simply getting a quick one-time listing without an ongoing interactive display.

PART 7Text Editors

nano is a simple, beginner-friendly command-line text editor commonly used for quickly viewing and editing configuration files (Part 8, below) directly within the terminal. Compared to other Linux text editors (such as vim or emacs, which have steeper learning curves but more advanced capabilities), nano displays its available keyboard commands directly at the bottom of the screen, making it especially approachable for technicians who need to make a quick edit without memorizing a separate command set first.

Exam Angle

For the A+ exam, recognize nano specifically as the approachable, beginner-friendly choice among Linux text editors — a scenario describing a technician needing to make a quick edit to a configuration file directly from the command line, without extensive editor experience, points to nano as a reasonable, low-friction choice.

PART 8Common Configuration Files

/etc/passwd

Contains basic information about every user account on the system — username, user ID (UID), group ID (GID), home directory path, and default shell. Despite the name, modern Linux systems do not store actual password hashes here (this file is world-readable, which would be a serious security risk if it held real passwords) — that sensitive data lives in /etc/shadow instead.

/etc/shadow

Contains the actual encrypted password hashes for user accounts, along with password aging/expiration information. Unlike /etc/passwd, this file has tightly restricted permissions, readable only by the root account — a deliberate security separation between basic account information (passwd) and sensitive credential data (shadow).

/etc/hosts

A local, manually-editable file mapping hostnames directly to IP addresses, checked by the system before querying DNS (objective 2.1/2.3) — conceptually identical in role to the Windows hosts file. Commonly used to manually define a hostname-to-IP mapping for testing purposes, or to override/block a specific domain at the local machine level.

/etc/fstab

"File system table" — defines which filesystems/drives should be automatically mounted at boot, and at what mount point each one should appear, eliminating the need to manually run mount for every drive after each restart. Misconfiguring this file is a classic cause of a Linux system failing to boot properly, since the system expects to mount the listed filesystems during startup.

/etc/resolv.conf

Specifies which DNS server(s) the system should use for name resolution (objective 2.1/2.3/2.6 concepts) — the Linux equivalent of manually configured DNS server settings in Windows' network adapter properties. On many modern systems this file is automatically managed/overwritten by network management services rather than edited directly by hand.

Common Pitfall — passwd vs. shadow

A frequently tested point of confusion: many people assume /etc/passwd stores passwords given its name, but it does not — actual password hashes live exclusively in the much more restricted /etc/shadow file. Recognizing this passwd/shadow separation, and why it exists (passwd must remain widely readable for normal system operations to look up basic account info, while shadow must stay locked down since it holds the sensitive credential data), is a core, testable security concept.

PART 9OS Components

systemd The modern init system used by most major Linux distributions today — the first process started by the kernel at boot, responsible for starting, stopping, and managing all other system services (often called "units" in systemd terminology) throughout the system's runtime, and for orchestrating an orderly, parallelized boot sequence.
Kernel The core of the operating system itself — the layer that directly manages hardware (CPU, memory, storage, devices) and provides the fundamental services that everything else (including systemd, and ultimately every user application) relies on. "Linux" technically refers specifically to the kernel; a complete, usable operating system built around that kernel plus a collection of additional software is what constitutes a full distribution.
Bootloader The very first software that runs when a computer powers on (after firmware/BIOS-UEFI initialization), responsible for loading the Linux kernel into memory and starting the boot process. GRUB (GRand Unified Bootloader) is the most common Linux bootloader, and on systems with more than one installed operating system, the bootloader is typically also what presents a boot menu allowing the user to choose which OS to start.

The Boot Sequence, Tied Together

Putting the pieces in order: firmware (BIOS/UEFI, objective 3.5) initializes hardware first, then hands off control to the bootloader (commonly GRUB), which loads the kernel into memory, which in turn starts systemd as the very first user-space process — and systemd then brings up every other service and ultimately the full working system from there.

PART 10Root Account

The root account is Linux's superuser/administrator account, possessing unrestricted access to every file, every system setting, and every process on the system — directly analogous in role to the Administrator account on Windows. Because root has essentially no built-in safety restrictions on what it can do (including the ability to delete critical system files or break the system entirely), modern Linux best practice strongly favors using sudo (Part 3, above) to perform specific administrative actions as needed, rather than staying logged in directly as root for routine, everyday work.

Exam Angle

Recognize root as the Linux equivalent of the Windows Administrator account in terms of privilege level, while also recognizing that the prevailing best practice — using sudo for individual elevated commands rather than working as root directly — reflects the same general security principle of least privilege that recurs throughout the exam: grant only the access actually needed for a specific task, rather than operating with maximum privilege by default.

Final Exam Reminders

su = switches the whole session (target's password). sudo = elevates one command (your own password). sudo is the modern best practice.

apt = Debian/Ubuntu family. dnf = Red Hat/Fedora family. Different commands, same fundamental job.

du = how big is this folder. df = how full is this drive. Easy to confuse by name alone.

top = live, continuously updating. ps = one-time snapshot, scriptable/pipeable.

/etc/passwd = basic account info, world-readable. /etc/shadow = actual password hashes, root-only. Passwords are NOT in passwd despite the name.

/etc/fstab = controls what mounts automatically at boot; misconfiguration can break booting.

Boot order = firmware → bootloader (GRUB) → kernel → systemd → rest of the system.

root = Linux's unrestricted superuser account, equivalent in role to Windows Administrator.
