OVERVIEWIntroduction to Wireless Security

Wireless networks broadcast their signal through open air, reachable by any device within range — which means securing a Wi-Fi network requires two separate but related things: encryption to scramble the data traveling over the air so it can't be read by an eavesdropper, and authentication to verify that whoever is connecting (or whatever server is granting access) is actually who they claim to be. Objective 2.3 covers both halves of this picture.

The first half, protocols and encryption, traces the evolution of Wi-Fi security standards — WPA2, WPA3, and the underlying encryption algorithms (TKIP and AES) each protocol relies on. The second half, authentication, covers the broader frameworks used to verify identity, both for network access specifically (RADIUS, TACACS+) and more generally across an environment (Kerberos, multifactor authentication).

Core Concept — Encryption Protects Data in Transit; Authentication Protects Access

It's easy to blur these two concepts together, but they solve different problems. Encryption (WPA2/WPA3, TKIP/AES) makes wireless traffic unreadable to anyone intercepting it over the air. Authentication (RADIUS, TACACS+, Kerberos, MFA) verifies that the party requesting access is legitimate before access is even granted. A network can theoretically have strong encryption and weak authentication, or vice versa — the exam expects you to recognize which concern a given technology actually addresses.

SECTION 1Protocols and Encryption

Wi-Fi security has evolved through several generations of protocols, each replacing the last as weaknesses were discovered and stronger encryption became standard.

WPA2Long-Standing Standard
Wi-Fi Protected Access 2 has been the dominant wireless security standard for most of the last two decades, built around AES encryption. It remains widely deployed and broadly compatible, though it has known vulnerabilities (such as offline dictionary attacks against a captured handshake) that WPA3 was designed to address.
WPA3Current Standard
The successor to WPA2, offering stronger encryption and improved protection against offline password-guessing attacks through a more secure handshake process. WPA3 is the current recommended standard for new wireless deployments, though it requires compatible hardware on both the access point and client device.
TKIPDeprecated
Temporal Key Integrity Protocol was an encryption method introduced to improve on the original WEP standard's weak encryption, and was used with early WPA. TKIP is now considered outdated and insecure by modern standards, having been superseded by AES.
AESCurrent Encryption Standard
Advanced Encryption Standard is the strong, modern encryption algorithm used by WPA2 and WPA3. AES is a widely trusted encryption standard used well beyond wireless networking, and its adoption is what actually delivers the security improvement WPA2 provided over the earlier WEP/TKIP era.

Exam Angle — Protocol vs. Encryption Algorithm

WPA2 and WPA3 are the overall security protocols — the full standard governing how a wireless network authenticates clients and manages encryption. TKIP and AES are the encryption algorithms that a protocol uses underneath. WPA2 is associated with AES (its intended encryption method) but historically could also run with the older, weaker TKIP for backward compatibility — recognizing that TKIP paired with WPA2 represents a weaker configuration than AES paired with WPA2 is a frequently tested distinction.

Never Use TKIP or WEP for New Deployments

TKIP (and the even older WEP it replaced) should never be selected for a new or updated wireless deployment — both are considered cryptographically broken by modern standards. If a scenario describes configuring a new access point, the correct choice is always the strongest protocol/encryption combination the hardware supports, which today means WPA3 (or WPA2 with AES if WPA3 isn't available), never TKIP.

SECTION 2Authentication

Beyond encrypting the data itself, a network needs a way to verify the identity of whoever is trying to connect. This objective names four authentication concepts, two of which are network-access-specific server protocols, and two of which are broader identity/verification concepts.

RADIUSRemote Authentication Dial-in User Service
What it doesA widely used client-server protocol that centralizes authentication, authorization, and accounting (AAA) for network access — a wireless access point, VPN concentrator, or switch forwards a connecting user's credentials to a central RADIUS server, which decides whether to grant access
Typical useEnterprise Wi-Fi authentication (e.g., WPA2/WPA3-Enterprise mode), where each user authenticates with their own individual network credentials rather than a single shared network password
TACACS+Terminal Access Controller Access-Control System Plus
What it doesSimilar in purpose to RADIUS — a centralized AAA protocol — but developed by Cisco and offering more granular control, particularly around authorization (what an authenticated user is allowed to do, not just whether they can get in)
Typical useAuthenticating administrative access to network devices (routers, switches), especially in Cisco-centric network environments
KerberosNetwork Authentication Protocol
What it doesA ticket-based authentication protocol that verifies identity using time-limited, encrypted "tickets" issued by a trusted authority, rather than repeatedly transmitting a password — the underlying authentication protocol Windows Active Directory domains rely on
Typical useAuthenticating users and services within a Windows Active Directory domain environment, providing single sign-on across domain resources
MFAMultifactor Authentication
What it doesRequires two or more independent categories of proof of identity — something you know (a password), something you have (a hardware token or phone), or something you are (a biometric) — rather than relying on a single factor alone
Typical useLayered on top of virtually any authentication system (including RADIUS-based Wi-Fi logins) to significantly reduce the risk of a compromised password alone granting unauthorized access — directly connecting to Objective 2.1's broader MFA coverage

RADIUS vs. TACACS+ — A Quick Distinguishing Detail

Both protocols centralize authentication, but TACACS+ separates authentication, authorization, and accounting into distinct processes and encrypts the entire packet payload, while RADIUS traditionally encrypts only the password portion of a packet and bundles authentication and authorization together more tightly. In practice, exam scenarios most often distinguish them by vendor association and use case: RADIUS is the more universal, vendor-neutral standard commonly used for Wi-Fi/VPN authentication, while TACACS+ is Cisco-originated and favored for granular administrative device access control.

Exam Angle — Kerberos as "Not Just for Wireless"

Although this objective is framed around wireless security, Kerberos itself isn't a wireless-specific protocol — it's the general authentication backbone of a Windows Active Directory domain, used for logging into domain resources whether the connection happens over Wi-Fi or a wired connection. Recognize Kerberos by its ticket-based mechanism and its tight association with Active Directory rather than assuming it's exclusively a wireless technology.

REFERENCEQuick Reference Cards

Protocol/Encryption Strength Ranking

  • Strongest, current — WPA3 (AES-based, improved handshake)
  • Strong, widely deployed — WPA2 with AES
  • Weak, avoid — WPA2 with TKIP, or TKIP alone
  • Broken, never use — WEP (and TKIP by extension)

Authentication Method → Typical Environment

  • Enterprise Wi-Fi/VPN, individual logins — RADIUS
  • Cisco network device admin access — TACACS+
  • Windows AD domain login/SSO — Kerberos
  • Layered on top of any of the above — MFA

Key Distinguishing Traits

  • RADIUS — vendor-neutral, password portion typically encrypted
  • TACACS+ — full packet encryption, separates AAA functions
  • Kerberos — ticket-based, no repeated password transmission
  • MFA — defined by combining factor categories, not a single protocol

Encryption vs. Authentication — Quick Sort

  • Protects data in transit — WPA2/WPA3, TKIP/AES
  • Verifies identity before granting access — RADIUS, TACACS+, Kerberos, MFA

Final Exam Reminders

WPA2/WPA3 are protocols; TKIP/AES are the encryption algorithms they use — don't treat these two pairs as interchangeable; a question about "the standard" is asking about WPA2/WPA3, while a question about "the encryption method" is asking about TKIP/AES.

TKIP (and WEP) should never appear as the correct choice for a new or secure deployment — both are deprecated and cryptographically broken; WPA3 (or WPA2 with AES) is always the stronger answer.

RADIUS and TACACS+ both centralize authentication (AAA), but TACACS+ is Cisco-associated with more granular authorization and full-packet encryption, while RADIUS is the more universal standard for Wi-Fi/VPN-style access.

Kerberos is ticket-based and is the authentication backbone of Active Directory — not a wireless-specific protocol, even though it appears under this wireless-focused objective.

Multifactor authentication is defined by combining independent factor categories (something you know/have/are), not by any single specific technology — recognize an MFA scenario by the presence of two or more distinct proof types, not by a brand name.
