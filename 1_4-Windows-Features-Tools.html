OVERVIEWIntroduction to Windows Built-In Tools

Windows ships with a large set of built-in graphical utilities for monitoring, configuring, and troubleshooting the system — no third-party software required. Objective 1.4 covers the specific tools a technician is expected to know: what each one is for, how to launch it, and which situation calls for which tool. Nearly every tool in this objective can be launched by typing its executable name (often ending in .msc or .exe) directly into the Run dialog (Win + R) or Start menu search — a detail worth memorizing since the exam frequently references tools by that exact filename.

This objective covers three groups. Task Manager is the everyday, at-a-glance tool for processes, performance, and startup items. MMC snap-ins are specialized administrative consoles, each focused on a single area of system management, all built on the shared Microsoft Management Console framework. And additional tools covers a set of standalone utilities that round out a technician's diagnostic toolkit.

Core Concept — Know the Filename, Not Just the Name

Every tool in this objective has both a friendly display name ("Device Manager") and an executable/console filename (devmgmt.msc) used to launch it directly. The exam tests both directions — recognizing what a tool does when given its filename, and recalling the filename when given a scenario. Treat the two as inseparable: learn each tool as a name-and-filename pair, not just a name.

SECTION 1Task Manager

Task Manager is the most frequently used everyday Windows utility, providing a real-time view of what's running on the system and giving a technician the ability to end unresponsive programs, inspect resource usage, and manage startup items — all from one window. It can be launched via Ctrl+Shift+Esc, via Ctrl+Alt+Delete, or by right-clicking the taskbar.

Processes
Lists all currently running applications and background processes, along with their real-time CPU, memory, disk, and network usage — the first place to look for a single process consuming excessive resources or an unresponsive application to end.
Performance
Displays real-time graphs of overall system resource usage — CPU, memory, disk, network, and (if present) GPU — useful for quickly assessing whether the system as a whole is under heavy load rather than looking at any single process.
Startup
Lists applications configured to launch automatically when Windows starts, along with each one's relative impact on startup time — the primary tool for diagnosing and fixing a slow-booting system by disabling unnecessary startup programs.
Users
Shows all user accounts currently logged into the system (including disconnected sessions) along with their individual resource usage — useful on shared or multi-session machines to see which user's session is consuming resources.
Services
Lists Windows services and their current running/stopped status, with the ability to start, stop, or restart a service directly — a quick way to check or control a specific background service without opening the full Services console.

Exam Angle — Matching the Task Manager Tab to the Symptom

"The computer boots slowly" → Startup tab. "One specific application is frozen or consuming all the CPU" → Processes tab. "The whole system feels sluggish, unclear why" → Performance tab. "A shared computer, need to see who else is logged in" → Users tab. "A specific background service needs to be restarted" → Services tab. Matching the described symptom to the correct tab is a frequently tested pattern.

SECTION 2Microsoft Management Console (MMC) Snap-Ins

The Microsoft Management Console (MMC) is a framework that hosts individual administrative tools, called snap-ins, each focused on managing one specific area of the system. Every snap-in below can be launched directly by typing its .msc filename into the Run dialog.

Event Viewereventvwr.msc
PurposeDisplays detailed logs of system, security, and application events — errors, warnings, and informational messages recorded by Windows and installed applications
Common useThe first place to look when diagnosing an unexplained crash, failed service, or security event — logs are timestamped and categorized by severity and source
Disk Managementdiskmgmt.msc
PurposeA graphical utility for viewing and managing disks, partitions, and volumes — creating, deleting, resizing, formatting, and assigning drive letters
Common useThe graphical counterpart to the command-line diskpart tool (Objective 1.5) — generally the preferred tool for straightforward, one-off partition and volume tasks
Task Schedulertaskschd.msc
PurposeCreates, views, and manages tasks that run automatically on a schedule or in response to a specific trigger (e.g., at logon, at a specific time, or when an event occurs)
Common useAutomating scripts (Objective 4.8), scheduling routine maintenance tasks, or scheduling backups (Objective 4.3) to run without manual intervention
Device Managerdevmgmt.msc
PurposeLists all hardware devices recognized by Windows, organized by category, showing driver status and allowing drivers to be updated, rolled back, disabled, or uninstalled
Common useThe primary tool for diagnosing hardware driver problems — a device showing a warning icon here typically points directly to a driver conflict or failure
Certificate Managercertmgr.msc
PurposeViews and manages digital certificates installed for the current user — including personal certificates, trusted root certification authorities, and other certificate stores
Common useTroubleshooting certificate warnings (Objective 3.4), installing a needed certificate, or verifying whether a specific certificate is trusted on the machine
Local Users and Groupslusrmgr.msc
PurposeManages local (non-domain) user accounts and security groups — creating accounts, resetting passwords, and assigning group membership
Common useThe graphical counterpart to the command-line net user command (Objective 1.5); notably unavailable on Windows Home editions, which lack this snap-in
Performance Monitorperfmon.msc
PurposeTracks detailed, customizable performance counters over time, well beyond what Task Manager's Performance tab shows — supports logging data over extended periods for deeper analysis
Common useDiagnosing intermittent or hard-to-reproduce performance problems that require historical data rather than just a real-time snapshot
Group Policy Editorgpedit.msc
PurposeConfigures local Group Policy settings — security options, restrictions, and system behavior — on a single machine, independent of a domain-based Group Policy
Common useConfiguring policy on a standalone or workgroup machine not joined to a domain; like Local Users and Groups, notably unavailable on Windows Home editions

Home Edition Limitation — A Frequently Tested Detail

Both Local Users and Groups (lusrmgr.msc) and Group Policy Editor (gpedit.msc) are not included in Windows Home editions — a detail that connects directly back to Objective 1.3's Windows edition feature comparisons. A scenario describing either tool being unavailable on a specific machine is very likely describing a Home edition limitation, not a broken installation.

SECTION 3Additional Tools

These standalone utilities round out the built-in Windows toolkit, each launched by its own .exe filename rather than through the MMC framework.

System Informationmsinfo32.exe
PurposeDisplays a comprehensive summary of the system's hardware configuration, installed software environment, and system components in one consolidated report
Common useQuickly gathering full system specs and configuration details for documentation, asset management (Objective 4.1), or advanced troubleshooting without checking multiple separate locations
Resource Monitorresmon.exe
PurposeProvides a much more detailed, granular view of CPU, memory, disk, and network usage than Task Manager — including which specific files a process has open and which processes are using which network connections
Common useDigging deeper than Task Manager allows — for example, identifying exactly which process is holding a file open and preventing it from being deleted or modified
System Configurationmsconfig.exe
PurposeConfigures system boot options (including Safe Mode boot), manages startup services, and adjusts general system settings related to how Windows starts
Common useSelectively enabling/disabling startup services (as distinct from Task Manager's startup app list) and configuring boot into Safe Mode for troubleshooting
Disk Cleanupcleanmgr.exe
PurposeIdentifies and removes unnecessary files — temporary files, recycle bin contents, old Windows update files, and other reclaimable space — to free up disk space
Common useA quick first step when a drive is running low on free space, before considering more involved storage solutions
Disk Defragmentdfrgui.exe
PurposeReorganizes fragmented data on a traditional hard disk drive (HDD) so related file pieces sit closer together physically, improving read/write performance
Common useMaintaining performance on HDD-based systems specifically; not needed (and not recommended) for solid-state drives (SSDs), which don't suffer the same fragmentation-related performance penalty and can wear unnecessarily from excess writes
Registry Editorregedit.exe
PurposeDirectly views and edits the Windows Registry — the hierarchical database storing low-level configuration settings for the OS, hardware, and installed applications
Common useAdvanced troubleshooting and configuration changes not exposed through any standard graphical settings interface — used carefully, since incorrect edits can destabilize or break the OS

Registry Editor — High Risk, Last Resort

Unlike most other tools in this objective, regedit.exe offers no built-in safety net — there's no confirmation dialog stopping a technician from deleting or altering a critical registry key, and a wrong edit can prevent Windows from booting. Best practice is to back up the specific registry key (or export the full registry) before making a change, and to use the Registry Editor only when no safer, purpose-built tool accomplishes the same task.

SSD vs. HDD — Why Defragmenting Matters for Only One

Disk Defragment (dfrgui.exe) exists to counteract fragmentation on spinning hard disk drives, where a mechanical read/write head has to physically move to different locations to read a fragmented file. Solid-state drives have no moving parts and near-uniform access time regardless of where data sits, so defragmenting an SSD provides no performance benefit and simply consumes some of its limited write endurance — modern versions of the tool will actually run an SSD-appropriate "optimization" (like TRIM) instead of true defragmentation when it detects an SSD.

"Which Tool Do I Need?" — Common Scenarios

  • Slow boot time — Task Manager Startup tab, or msconfig.exe
  • Unexplained crash/error — Event Viewer (eventvwr.msc)
  • Driver problem — Device Manager (devmgmt.msc)
  • Low disk space — Disk Cleanup (cleanmgr.exe)
  • File won't delete, "in use" — Resource Monitor (resmon.exe)

Graphical vs. Command-Line Counterparts

  • Disk Management ↔ diskpart (Obj. 1.5)
  • Local Users and Groups ↔ net user (Obj. 1.5)
  • Group Policy Editor ↔ gpupdate/gpresult (Obj. 1.5)

Not Available on Windows Home

  • lusrmgr.msc — Local Users and Groups
  • gpedit.msc — Group Policy Editor
  • Connects to — Objective 1.3's edition comparisons

Handle-With-Care Tools

  • regedit.exe — no undo; back up before editing
  • diskmgmt.msc — deleting/formatting a volume destroys data
  • dfrgui.exe — don't run traditional defrag on an SSD

Final Exam Reminders

Learn each tool as a name-and-filename pair — the exam tests recognition in both directions, and scenario questions often reference the filename directly (e.g., "which tool would you launch with devmgmt.msc?").

lusrmgr.msc and gpedit.msc are both absent from Windows Home editions — this is one of the most reliably tested cross-references between this objective and Objective 1.3.

Resource Monitor (resmon.exe) goes deeper than Task Manager, especially for identifying which process has a specific file locked open — know this as the specific tool for that specific symptom.

Disk Defragment is for HDDs, not SSDs — running it unnecessarily on an SSD provides no benefit and consumes write endurance; modern Windows detects the drive type and adjusts its behavior accordingly.

Registry Editor changes take effect immediately with no confirmation and no built-in undo — always back up the relevant key (or the full registry) before making a change, and treat it as a last-resort tool.

Task Manager's Startup tab and msconfig.exe both relate to what runs at boot, but aren't identical — Task Manager's Startup tab manages startup applications, while msconfig also covers boot options like Safe Mode and startup services, giving broader control over the boot process itself.
